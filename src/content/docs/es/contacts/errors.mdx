## Tabla de errores

| HTTP | `error` | Cuándo |
| ---- | ------- | ------ |
| 400  | `invalid_contact_id` | `contact_id` no coincide con `^ct_[0-9a-f]{32}$` |
| 400  | `invalid_cursor` | Cursor opaco corrupto |
| 402  | `contact_quota_exceeded` | Se alcanzó la cuota de contactos distintos del ciclo |
| 404  | `contact_not_found` | ID inválido o de otra organización |
| 404  | `contact_picture_unavailable` | Caso raro — falló la generación de la URL prefirmada de la foto en esta solicitud. La ausencia de foto (sin storage, upload fallido, contacto sin foto) **no** devuelve 404: ver [Foto de Perfil](/es/contacts/profile-picture/) |
| 429  | `refresh_rate_limited` | Límite de refresh por minuto excedido |

Un id de contacto accedido bajo el `{alias}` **equivocado** también se
manifiesta como **`contact_not_found`** (404) — revisa el `number_alias` del
envelope. Para el número principal las rutas planas (`/v1/contacts/{id}`,
etc.) también están disponibles como atajo; para números extra usa siempre la
forma anidada con el `{alias}` correcto.

## Ejemplo de respuesta 402

Devuelto cuando la organización intenta contactar, vía Turbo Notify, a un
contacto que pasa a estar contado en el ciclo actual — un contacto
**nuevo** o un contacto **recurrente** aún no contado en este ciclo — y la
cuota de contactos distintos del ciclo ya está agotada.

<ApiResponse status={402}>
```json
{
  "error": "contact_quota_exceeded",
  "message": "Distinct-contacts quota exceeded for tier SOLO (100/100 this cycle)",
  "details": {
    "quota": 100,
    "used": 100,
    "resets_at": "2026-08-01T00:00:00Z",
    "tier": "SOLO"
  }
}
```
</ApiResponse>

**Acción recomendada:** actualizar el plan. A diferencia de 429, el 402 no
tiene `Retry-After` — el error es estructural (el ciclo de facturación
evaluado debe cerrar, en `resets_at`, o el tier debe subir).

## 402 vs 429 — cuándo aparecen

| | 402 Payment Required | 429 Too Many Requests |
| - | --------------------- | ---------------------- |
| Semántica | Estructural — "actualiza el plan" | Temporal — "reintenta después" |
| Header | — | `Retry-After: <segundos>` |
| Reset | Al fin del ciclo de facturación evaluado (`resets_at`), o upgrade | En segundos/minutos |
| Cuándo | Cuota del ciclo | Burst protection |

Ver también: [Uso y Cuota](/es/usage/quota/).
