**Fecha:** 2026-06-22
**Estado:** Aplicado

:::caution[Cambio de ruta — incompatible]
Este es un **cambio de ruta incompatible**. Toda llamada a mensajes, contactos y
grupos debe migrar a la ruta anidada bajo el número (`/v1/numbers/{alias}/…`).
Las rutas planas antiguas (`/v1/messages`, `/v1/contacts`, `/v1/groups` y sus
sub-rutas) ahora devuelven **404**.
:::

## Qué cambió

### Mensajes, contactos y grupos siempre bajo el número

Los mensajes, contactos y grupos pasan a estar **siempre asociados a un número**
de tu organización. La API lo expresa de forma **estructural**: las rutas residen
bajo la ruta del número, identificado por `{alias}` (`main` para el número
principal o el alias de un número extra).

| Antes (plano — ahora 404) | Ahora (anidado por número) |
| ------------------------- | -------------------------- |
| `POST /v1/messages` | `POST /v1/numbers/{alias}/messages` |
| — (no existía lista pública) | `GET /v1/numbers/{alias}/messages` (lista por cursor — **nuevo**) |
| `GET /v1/messages/{id}` | `GET /v1/numbers/{alias}/messages/{id}` |
| `GET /v1/messages/{id}/status` | `GET /v1/numbers/{alias}/messages/{id}/status` |
| `GET /v1/messages/{id}/reactions` | `GET /v1/numbers/{alias}/messages/{id}/reactions` |
| `GET /v1/messages/{id}/receipts` | `GET /v1/numbers/{alias}/messages/{id}/receipts` |
| `POST /v1/messages/{id}/reply` | `POST /v1/numbers/{alias}/messages/{id}/reply` |
| `POST /v1/messages/{id}/edit` | `POST /v1/numbers/{alias}/messages/{id}/edit` |
| `POST /v1/messages/{id}/delete` | `POST /v1/numbers/{alias}/messages/{id}/delete` |
| `POST /v1/messages/{id}/react` | `POST /v1/numbers/{alias}/messages/{id}/react` |
| `POST /v1/typing-indicator` | `POST /v1/numbers/{alias}/typing-indicator` |
| `GET /v1/contacts` | `GET /v1/numbers/{alias}/contacts` |
| `GET /v1/contacts/{id}` | `GET /v1/numbers/{alias}/contacts/{id}` |
| `GET /v1/contacts/{id}/profile-picture` | `GET /v1/numbers/{alias}/contacts/{id}/profile-picture` |
| `GET /v1/contacts/quota` | `GET /v1/numbers/{alias}/contacts/quota` |
| `POST /v1/contacts/{id}/refresh` | `POST /v1/numbers/{alias}/contacts/{id}/refresh` |
| `GET /v1/groups` | `GET /v1/numbers/{alias}/groups` |
| `GET /v1/groups/{id}` | `GET /v1/numbers/{alias}/groups/{id}` |
| `GET /v1/groups/{id}/picture` | `GET /v1/numbers/{alias}/groups/{id}/picture` |

### El envío ya no acepta `from` en el body

Como el remitente ahora es el número del path, el campo `from` en el cuerpo de
envío fue **eliminado**. Para enviar desde el número principal usa
`POST /v1/numbers/main/messages`; para un número extra usa su alias
(`POST /v1/numbers/{alias}/messages`). El campo `to` (destinatario) no cambia y
sigue aceptando `number`, `group_id` o `contact_id`.

### Identificadores únicos, pero no direccionables por sí solos

Los ids públicos (`msg_…`, `ct_…`, `grp_…`) siguen siendo globalmente únicos, pero
**ya no son direccionables por sí solos**: para leer o actuar sobre un recurso por
id necesitas el `number_alias` al que pertenece. Ese handle está **siempre
presente en el envelope** de cada webhook, ítem de `GET /v1/events` y respuesta de
envío — léelo de ahí y úsalo en las llamadas por id posteriores. Acceder a un id
bajo el alias equivocado devuelve **404**.

### Clave de idempotencia por alias

El alcance de la clave de idempotencia (`Idempotency-Key`) pasa a ser
`(organización, number_alias, clave)`. La misma clave en dos aliases diferentes
produce **dos envíos independientes**.

### `contact.quota.*` ahora por número

Los eventos `contact.quota.warning` y `contact.quota.exceeded` pasan a incluir el
campo **`number_alias` en el envelope** (justo debajo de `organization_id`),
identificando el número cuya cuota de contactos se alcanzó. El `data` del evento
no cambia. `number_alias` sigue **omitido** solo en `storage.*` y en los eventos
de cuota de mensaje (`message.quota.*`).

### `GET /v1/events` acepta el filtro `number_alias`

La ruta de polling `GET /v1/events` gana un parámetro opcional **`number_alias`**
que restringe la respuesta a los eventos de un único número. Las superficies de
cuenta (`GET /v1/usage`, `GET /v1/usage/messages`, `GET /v1/events`, `storage.*`)
permanecen **a nivel raíz** y no se vieron afectadas por el cambio de ruta.

## Compatibilidad

Pre-producción: el cambio es incompatible sin capa de transición. Las rutas
planas devuelven 404 de inmediato. Migra toda llamada a la ruta anidada y empieza
a leer `number_alias` del envelope para las llamadas por id.
