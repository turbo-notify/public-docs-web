**Fecha:** 2026-06-25
**Estado:** Aplicado

:::note[Las rutas planas funcionan de nuevo]
Entre el 2026-06-22 y el 2026-06-25, las rutas planas (`/v1/messages`,
`/v1/contacts`, `/v1/groups` y sus sub-rutas) devolvían **404** — ver [Rutas
anidadas por número](/es/changelog/2026-06-22-number-scoped-routes/). A partir
de esta versión vuelven a funcionar **permanentemente** como forma corta para
el número principal, con una respuesta idéntica a la forma anidada. Ya no
devuelven 404 por ser planas — solo si la organización no tiene un número
principal registrado.
:::

## Qué cambió

A partir de esta versión, todas las operaciones del número principal pueden
realizarse directamente sin especificar el alias en la URL:

| Nueva ruta plana | Equivalente |
|---|---|
| `POST /v1/messages` | `POST /v1/numbers/main/messages` |
| `GET  /v1/messages` | `GET  /v1/numbers/main/messages` |
| `GET  /v1/messages/{id}` | `GET  /v1/numbers/main/messages/{id}` |
| `GET  /v1/contacts` | `GET  /v1/numbers/main/contacts` |
| `GET  /v1/contacts/quota` | `GET  /v1/numbers/main/contacts/quota` |
| `GET  /v1/groups` | `GET  /v1/numbers/main/groups` |
| `POST /v1/typing-indicator` | `POST /v1/numbers/main/typing-indicator` |
| *(y todas las sub-rutas)* | |

La forma `/v1/numbers/main/…` sigue funcionando con normalidad y produce
respuestas idénticas — la forma anidada es la canónica; la forma plana es un
atajo permanente válido solo para el número principal. Para **números
extras**, continúa usando `/v1/numbers/{alias}/…` — no tienen forma plana.

El envelope de webhook/polling de una operación hecha por la ruta plana lleva
`number_alias: "main"`, indistinguible de una operación hecha por la ruta
anidada.

Este cambio no requiere ninguna modificación en integraciones existentes.
