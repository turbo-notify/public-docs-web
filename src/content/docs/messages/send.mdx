Envie mensagens pelo Turbo Notify de forma simples, segura e em conformidade com as <ExternalLink href="https://www.whatsapp.com/legal/business-policy/">políticas do WhatsApp</ExternalLink>.

O corpo de `POST /v1/numbers/{alias}/messages` (ou o atalho
`POST /v1/messages` para o número principal) usa um objeto
**aninhado `content`** para transportar o payload da mensagem. O tipo é
inferido automaticamente pelo campo âncora presente em `content`
(`text`, `image_url`, `latitude`, `start_at`, …) — **não envie** um campo
`content_type` no request: ele nunca é aceito (incluí-lo retorna `422`).
Suporta texto, localização, contato, calendário e
mídia (`image`, `video`, `audio`, `document`, `sticker` — veja
[Envio de Mídia](/messages/send-media/)).

Para citar (responder) uma mensagem existente — qualquer variante de conteúdo — use o endpoint dedicado `POST /v1/messages/{message_id}/reply`, onde `{message_id}` é o id público da mensagem citada (`msg_{hex32}`). O body do reply contém apenas `content`. O webhook resultante é `message.replied` (em vez de `message.sent`); veja [Webhooks](/messages/webhook/#exemplo--messagereplied-inboundoutbound).

:::tip[Roteamento por número]
- **Número principal** → `POST /v1/messages` (rota plana) **ou** `POST /v1/numbers/main/messages` — as duas formas são idênticas.
- **Número extra** → `POST /v1/numbers/{alias}/messages`, onde `{alias}` é o alias configurado no dashboard. [Saiba mais](/numbers/add/).
:::

## Envio básico

O envio mais simples exige apenas o número do destinatário e o texto da mensagem. O Turbo Notify usará automaticamente o número principal da sua conta como remetente.

    ```bash title="turbo-notify.sh"
    curl -X POST \
      https://api.turbonotify.com/v1/messages \
      -H "Authorization: Bearer SUA_CHAVE" \
      -H "Content-Type: application/json" \
      -d '{
        "to": {"number": "+5511999999999"},
        "content": {
          "text": "Ola, esta e uma mensagem enviada pelo Turbo Notify!"
    ```

## Erros possíveis

Veja os principais erros que podem ocorrer no envio de mensagens e como interpretá-los:

| Status | Código de erro          | Descrição                                         |
| :----: | ----------------------- | ------------------------------------------------- |
| `400`  | `invalid_json`          | O JSON da requisição está malformado ou inválido. |
| `403`  | `not_authorized`        | A chave de acesso está inválida ou ausente.       |
| `422`  | `sender_not_authorized` | O alias na URL não está ativo na conta.           |
| `429`  | `rate_limit_exceeded`   | Limite de envio do plano ultrapassado.            |
| `422`  | `contact_not_found`     | O `contact_id` informado não pertence ao organization.  |
| `422`  | `contacts_not_enabled`  | Envio por `contact_id` não configurado.           |
| `500`  | `internal_error`        | Erro interno inesperado no servidor.              |
| `503`  | `whatsapp_unavailable`  | O WhatsApp está temporariamente fora do ar.       |

## Status da mensagem

O status informa o andamento do processamento da mensagem. Para detalhes completos sobre cada status, consulte a documentação [Status](/messages/status/).

<ApiResponse
  status={202}
  body={{
    message_id: 'msg_abc123',
    status: { state: 'pending', at: '2025-07-16T10:00:00Z' },
  }}
/>

O retorno final do processamento chega via webhook com os eventos `message.sent`, `message.delivered`, `message.read` ou `message.send.failed`.

## Segurança e privacidade

Toda comunicação entre seu sistema e a API do Turbo Notify ocorre exclusivamente por HTTPS, assegurando que os dados estejam sempre criptografados durante o tráfego.

Para saber por quanto tempo as mensagens ficam disponíveis para consulta e operações, veja a documentação de [Retenção](/messages/retention/).

## Conteúdo rico — localização, contato e calendário

A partir de 2026-04-27 o `POST /v1/messages` aceita três variantes de
conteúdo rico além de `text`. Cada variante tem um campo âncora próprio
dentro do objeto `content` e é despachada para o WhatsApp como o tipo
nativo correspondente (`locationMessage`, `contactMessage`, `eventMessage`).

:::tip
A nomenclatura interna do WhatsApp é "evento"; usamos
`calendar` como variante de conteúdo no Turbo Notify para evitar
ambiguidade com o termo "event" usado em webhooks (ADR 2026-04-27 — rich content rendering).
:::

:::caution[Limitação de propagação — contas pessoais WhatsApp]
A variante `calendar` (campo âncora `start_at`) é uma feature **WhatsApp Business** (`eventMessage`).
Quando o destinatário é uma **conta pessoal** (não-Business), o servidor
WhatsApp remove os timestamps (`startTime`/`endTime`) durante a entrega.
O destinatário recebe a mensagem com todos os metadados úteis (`name`,
`description`, `join_link`, `location`) mas **sem horário** — o webhook
`message.received` correspondente preserva a variante `calendar` e
omite o campo `start_at` do body. Não há reclassificação como
`unsupported`.

O envio (`message.sent`) e o status de entrega (`message.delivered` /
`message.read`) funcionam normalmente; apenas o horário do card de
evento fica ausente no cliente do peer. Mitigação: garantir que a
conta destinatária seja WhatsApp Business antes de enviar `calendar`,
ou usar a variante `text` com link ICS quando o destinatário for
pessoal e o horário for crítico.
:::

### Como aparece no destinatário

Cada tipo aparece no WhatsApp do destinatário com a UI nativa:
**localização** com mapa e botão "Ver no mapa", **contato** com card
salvável, **calendário** com botão "Adicionar ao calendário".

Para visualizar exatamente como o evento `message.sent` correspondente
chega no seu webhook, abra o [Webhook Inspector](https://webhook.turbonotify.com/)
— o painel "Enriched" renderiza esses três tipos com cards dedicados.

## Envio para grupo

Disponível desde 2026-05-25. Para enviar a um grupo, o campo `to`
assume a forma de objeto `{ "group_id": "grp_..." }` em vez da string
de telefone usada em 1:1. Veja
[Visão geral de grupos](/groups/overview/) para detalhes do modelo.

```json title="POST /v1/messages — grupo"
{
  "to": { "group_id": "grp_e442553a56b14e2695f6acfd7d651b1a" },
  "content": {
    "text": "Bom dia, equipe"
  }
}
```

O campo `to` é polimórfico — aceita exatamente uma das três formas (sem `kind` nem `type`):

| Forma de `to` | Destino |
|---|---|
| `{ "number": "+5511999999999" }` | Mensagem 1:1 (pessoa) |
| `{ "group_id": "grp_..." }` | Mensagem para grupo |
| `{ "contact_id": "ct_..." }` | Mensagem 1:1 via ID de contato TN |

- As três formas são **mutuamente exclusivas** — envie exatamente uma.
- `group_id` é o identificador público `grp_{hex32}` recebido em
  webhooks/polling de `message.received` (`to.group_id`) ou nos
  eventos de [ciclo de vida de grupo](/groups/lifecycle-events/).
- O objeto `content` usa o mesmo schema de envios 1:1 (texto, imagem,
  vídeo, áudio, documento, sticker, location, contact, calendar) —
  sem mudanças.
- Para citar uma mensagem dentro do grupo, use o endpoint dedicado
  `POST /v1/numbers/{alias}/messages/{message_id}/reply`.

A resposta tem o shape padrão (`message_id`, `status`). O webhook
`message.sent` correspondente usa `to.group_id` (mesmo valor que você
enviou no request); o `number_alias` do envelope identifica a linha que
enviou — útil para correlacionar entregas inbound e outbound no mesmo grupo.

:::caution[Organization precisa estar no grupo]
A TN só envia para grupos onde sua linha (primary ou extra) é
participante. Tentar enviar para um `group_id` em que você não está
mais retorna 422 `not_group_member`. Re-entre no grupo via WhatsApp
(o webhook `group.joined` confirma) e tente novamente.
:::

:::tip[Quota não é fan-out]
Mensagem para grupo conta como **1 destinatário** no rate-limit diário,
independente de quantos participantes o grupo tenha. Quota de contatos
(`contact.quota.*`) não é afetada — grupos nunca materializam contatos
(ADR 2026-05-25).
:::

## Envio por contact_id

Use `to.contact_id` para enviar a um contato do catálogo TN sem informar o telefone.
O número é resolvido automaticamente pelo servidor a partir da tabela de contatos.

```json
{
  "to": { "contact_id": "ct_a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4" },
  "content": { "text": "Olá, tudo bem?" }
}
```

:::tip[Obtendo o contact_id]
O `contact_id` (formato `ct_{hex32}`) é retornado em webhooks de contato
(`contact.created`, `contact.updated`) e no endpoint `GET /v1/numbers/{alias}/contacts`.
:::
