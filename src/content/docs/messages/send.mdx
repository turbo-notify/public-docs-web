Envie mensagens pelo Turbo Notify de forma simples, segura e em conformidade com as <ExternalLink href="https://www.whatsapp.com/legal/business-policy/">políticas do WhatsApp</ExternalLink>.

O corpo de `POST /v1/numbers/{alias}/messages` (ou o atalho
`POST /v1/messages` para o número principal) usa um objeto
**aninhado `content`** para transportar o payload da mensagem. O tipo é
inferido automaticamente pelo campo âncora presente em `content`
(`text`, `image_url`, `latitude`, `start_at`, …) — **não envie** um campo
`content_type` no request: ele nunca é aceito (incluí-lo retorna `422`).
Suporta texto, localização, contato, calendário e
mídia (`image`, `video`, `audio`, `document`, `sticker` — veja
[Envio de mídia](/messages/send-media/)).

Para citar (responder) uma mensagem existente — qualquer variante de conteúdo — use o endpoint dedicado `POST /v1/messages/{message_id}/reply`, onde `{message_id}` é o id público da mensagem citada (`msg_{hex32}`). O body do reply contém apenas `content`. O webhook resultante é `message.replied` (em vez de `message.sent`); veja [Webhooks](/messages/webhook/#exemplo--messagereplied-inboundoutbound).

A mensagem citada precisa estar **dentro da [janela de leitura por retenção](/messages/retention/)** do seu tier: responder a uma mensagem mais antiga que a janela retorna `404 not_found` — a mesma resposta de uma mensagem inexistente.

:::tip[Roteamento por número]
- **Número principal** → `POST /v1/messages` (rota plana) **ou** `POST /v1/numbers/main/messages` — as duas formas são idênticas.
- **Número extra** → `POST /v1/numbers/{alias}/messages`, onde `{alias}` é o alias configurado no dashboard. [Saiba mais](/numbers/add/).
:::

## Envio básico

O envio mais simples exige apenas o número do destinatário e o texto da mensagem. O Turbo Notify usará automaticamente o número principal da sua conta como remetente.

## Menções (@mentions)

Para mencionar
alguém — a menção real do WhatsApp, com nome tocável e notificação no aparelho
do mencionado — escreva o token **`@<numero>`** diretamente no `text` (ou no
`caption` de mídia — veja [Envio de mídia](/messages/send-media/)): `@` seguido
do telefone do contato em **dígitos E.164, sem `+`**.

```json title="POST /v1/messages — texto com menção (1:1)"
{
  "to": { "number": "+5511988887777" },
  "content": {
    "text": "Olá @5511987650000, seu pedido chegou!"
  }
}
```

Menções brilham em grupos — mencione um participante pelo número:

```json title="POST /v1/messages — grupo mencionando um participante"
{
  "to": { "group_id": "grp_e442553a56b14e2695f6acfd7d651b1a" },
  "content": {
    "text": "Bom dia @5511987650000, pode validar o pedido de hoje?"
  }
}
```

**Não existe campo `mentions` no request** — a detecção é **implícita**, pelo
próprio texto (o mesmo modelo da inferência de tipo de conteúdo pelo campo
âncora). Todo token válido vira uma menção real no dispositivo do destinatário.

### Regras do token

| Regra | Comportamento |
|---|---|
| Sintaxe | `@` + 7–15 dígitos, delimitado por fronteira de palavra — `nome@dominio.com`, `@@123`, sequências com mais de 15 dígitos e `@+55…` **não** viram menção |
| Normalização | Números BR de 12 dígitos são normalizados para a forma canônica de 13 dígitos — o conteúdo persistido/devolvido carrega o token normalizado (ex.: `@551187650000` → `@5511987650000`) |
| Fail-open | Dígitos inválidos ou não normalizáveis permanecem **texto puro** — o envio nunca falha por causa de uma menção |
| Escopo | Funciona em 1:1 e em grupos, em `text` e em `caption` de `image`/`video`/`document` (`audio`/`sticker` não têm caption) |
| Eco simétrico | O token `@<numero>` que você recebe em `message.received` pode ser colado de volta no envio — menciona corretamente sem transformação manual |
| Quota | Mencionar alguém **nunca** consome quota de mensagens nem de contatos |

Depois do envio, a mensagem passa a carregar a estrutura `mentions`
(lista de `{contact_id?, name?, number}` — `contact_id` e `name` são omitidos
quando a menção não corresponde a um contato conhecido) em
[`GET /v1/messages/{message_id}`](/messages/get/) e no `data.mentions` dos
eventos [`message.sent`/`message.replied`/`message.edited`](/messages/webhook/)
— um `@<digitos>` literal no texto **só** é menção se constar dessa estrutura.

As mesmas regras de detecção valem para `POST .../messages/{message_id}/reply`
(o `text`/`caption` do reply) e para `POST .../messages/{message_id}/edit` (o
novo `text` da edição substitui **todo** o conjunto de menções da mensagem —
veja [Editar e deletar mensagens](/messages/edit-delete/#menções-em-edições)).

## Erros possíveis

Veja os principais erros que podem ocorrer no envio de mensagens e como interpretá-los:

| Status | Código de erro          | Descrição                                         |
| :----: | ----------------------- | ------------------------------------------------- |
| `400`  | `contact_not_found`     | O `contact_id` informado não pertence à organização.  |
| `400`  | `contacts_not_enabled`  | Envio por `contact_id` não configurado.           |
| `400`  | `not_group_member`      | Sua linha não é mais participante do `group_id` informado — veja [Envio para grupo](#envio-para-grupo). |
| `402`  | `feature_not_available` | Envio para grupo (`to.group_id`) requer plano `BUSINESS` ou superior — veja [Envio para grupo](#envio-para-grupo). |
| `402`  | `subscription_inactive` | Assinatura com pagamento pendente, encerrada ou trial expirado (`details.status`). Bloqueia todo envio até a assinatura voltar a ficar ativa. |
| `402`  | `contact_quota_exceeded` | Franquia de contatos distintos do ciclo atual esgotada — veja [Quota e uso](/usage/quota/). |
| `403`  | `not_authorized`        | A chave de acesso está inválida ou ausente.       |
| `403`  | `insufficient_scope`    | A chave de acesso não possui o escopo `messages:send` (resposta inclui `required_scope`). |
| `422`  | `validation_error`      | O corpo da requisição está malformado ou não passou na validação. A resposta traz `details.errors` com os campos rejeitados. |
| `422`  | `no_active_session`     | A organização não tem sessão WhatsApp conectada.  |
| `422`  | `sender_disconnected`   | O número extra do alias na URL está desconectado. |
| `422`  | `sender_not_found`      | O alias/número informado não corresponde a nenhum remetente da conta. |
| `422`  | `session_not_connected` | A sessão do remetente não está conectada no momento do envio. |
| `422`  | `extra_number_not_connected` | O número extra do alias na URL está registrado mas sua conexão como dispositivo vinculado não está ativa no momento. |
| `422`  | `group_not_owned_by_number` | O `group_id` informado pertence a outro número da conta, não ao alias do path. |
| `429`  | `messages_quota_exceeded` | Franquia de mensagens do ciclo atual esgotada — veja [Quota e uso](/usage/quota/). |
| `429`  | `send_rate_spacing`     | Envio antes do intervalo mínimo entre mensagens do seu tier — veja [Limites de uso](/messages/rate-limits/). |
| `429`  | `rate_limit_exceeded`   | Outro limite operacional do plano foi ultrapassado — veja [Limites de uso](/messages/rate-limits/). |
| `500`  | `internal_error`        | Erro interno inesperado no servidor.              |

## Status da mensagem

O status informa o andamento do processamento da mensagem. Para detalhes completos sobre cada status, consulte a documentação [Status](/messages/status/).

<ApiResponse
  status={202}
  body={{
    message_id: 'msg_abc123',
    status: { state: 'pending', at: '2025-07-16T10:00:00Z' },
  }}
/>

O retorno final do processamento chega via webhook com os eventos `message.sent`, `message.delivered`, `message.read` ou `message.send.failed`.

## Segurança e privacidade

Toda comunicação entre seu sistema e a API do Turbo Notify ocorre exclusivamente por HTTPS, assegurando que os dados estejam sempre criptografados durante o tráfego.

Para saber por quanto tempo as mensagens ficam disponíveis para consulta e operações, veja a documentação de [Retenção](/messages/retention/).

## Conteúdo rico — localização, contato e calendário

`POST /v1/messages` aceita três variantes de
conteúdo rico além de `text`. Cada variante tem um campo âncora próprio
dentro do objeto `content` e é despachada para o WhatsApp como o tipo
nativo correspondente (`locationMessage`, `contactMessage`, `eventMessage`).

| `content.display_name` | string | sim | 1–200 chars |
| `content.phones[]` | array | sim | 1–10 itens; `number` em E.164 |
| `content.phones[].label` | string | não | default `"Mobile"` (Mobile/Home/Work/...) |
| `content.emails[]` | array | não | 0–10; `address` validado como email |

| `content.title` | string | não | máx. 100 chars |
| `content.address` | string | não | máx. 500 chars |

O Turbo Notify gera o vCard server-side a partir desses campos —
você nunca precisa lidar com escaping vCard manualmente.

:::tip
A nomenclatura interna do WhatsApp é "evento"; usamos
`calendar` como variante de conteúdo no Turbo Notify para evitar
ambiguidade com o termo "event" usado em webhooks.
:::

:::caution[Limitação de propagação — contas pessoais WhatsApp]
A variante `calendar` (campo âncora `start_at`) é uma feature **WhatsApp Business** (`eventMessage`).
Quando o destinatário é uma **conta pessoal** (não-Business), o servidor
WhatsApp remove os timestamps (`startTime`/`endTime`) durante a entrega.
O destinatário recebe a mensagem com todos os metadados úteis (`name`,
`description`, `join_link`, `location`) mas **sem horário** — o webhook
`message.received` correspondente preserva a variante `calendar` e
omite o campo `start_at` do body. Não há reclassificação como
`unsupported`.

O envio (`message.sent`) e o status de entrega (`message.delivered` /
`message.read`) funcionam normalmente; apenas o horário do card de
evento fica ausente no cliente do peer. Mitigação: garantir que a
conta destinatária seja WhatsApp Business antes de enviar `calendar`,
ou usar a variante `text` com link ICS quando o destinatário for
pessoal e o horário for crítico.
:::

### Como aparece no destinatário

Cada tipo aparece no WhatsApp do destinatário com a UI nativa:
**localização** com mapa e botão "Ver no mapa", **contato** com card
salvável, **calendário** com botão "Adicionar ao calendário".

Para visualizar exatamente como o evento `message.sent` correspondente
chega no seu webhook, abra o [Webhook Inspector](https://webhook.turbonotify.com/)
— o painel "Enriched" renderiza esses três tipos com cards dedicados.

## Envio para grupo

Para enviar a um grupo, o campo `to`
assume a forma de objeto `{ "group_id": "grp_..." }` em vez de
`{ "number": "+5511999999999" }`, usada em 1:1. Veja
[Visão geral de grupos](/groups/overview/) para detalhes do modelo.

:::note[Requer plano BUSINESS ou superior]
Enviar mensagem (ou indicador de digitação) para um `group_id` exige a
feature `groups:messages`, disponível a partir do tier `BUSINESS`. Em
`FREE`/`SOLO` você ainda **recebe** mensagens de grupo, **lista grupos**
(`GET /v1/numbers/{alias}/groups`) e consulta detalhes — apenas o **envio**
outbound para grupo é bloqueado com `402`:

<ApiResponse
  status={402}
  body={{
    error: 'feature_not_available',
  }}
/>

Veja [Quota e uso](/usage/quota/#envio-para-grupos-exige-plano-business-ou-superior)
e [Limitações de grupos](/groups/limitations/).
:::

```json title="POST /v1/messages — grupo"
{
  "to": { "group_id": "grp_e442553a56b14e2695f6acfd7d651b1a" },
  "content": {
    "text": "Bom dia, equipe"
  }
}
```

O campo `to` é polimórfico — aceita exatamente uma das três formas (sem `kind` nem `type`):

| Forma de `to` | Destino |
|---|---|
| `{ "number": "+5511999999999" }` | Mensagem 1:1 (pessoa) |
| `{ "group_id": "grp_..." }` | Mensagem para grupo |
| `{ "contact_id": "ct_..." }` | Mensagem 1:1 via ID de contato Turbo Notify |

- As três formas são **mutuamente exclusivas** — envie exatamente uma.
- `group_id` é o identificador público `grp_{hex32}` recebido em
  webhooks/polling de `message.received` (`to.group_id`) ou nos
  eventos de [ciclo de vida de grupo](/groups/lifecycle-events/).
- O objeto `content` usa o mesmo schema de envios 1:1 (texto, imagem,
  vídeo, áudio, documento, sticker, location, contact, calendar) —
  sem mudanças.
- Para citar uma mensagem dentro do grupo, use o endpoint dedicado
  `POST /v1/numbers/{alias}/messages/{message_id}/reply`.

A resposta tem o shape padrão (`message_id`, `status`). O webhook
`message.sent` correspondente usa `to.group_id` (mesmo valor que você
enviou no request); o `number_alias` do envelope identifica a linha que
enviou — útil para correlacionar entregas inbound e outbound no mesmo grupo.

:::caution[A sua organização precisa estar no grupo]
O Turbo Notify só envia para grupos onde sua linha (principal ou extra) é
participante. Tentar enviar para um `group_id` em que você não está
mais retorna 400 `not_group_member`. Re-entre no grupo via WhatsApp
(o webhook `group.joined` confirma) e tente novamente.
:::

:::tip[Quota não é fan-out]
Mensagem para grupo conta como **1 destinatário** no rate-limit diário,
independente de quantos participantes o grupo tenha. Quota de contatos
(`contact.quota.*`) não é afetada — grupos nunca materializam contatos.
:::

## Envio por contact_id

Use `to.contact_id` para enviar a um contato do catálogo Turbo Notify sem informar o telefone.
O número é resolvido automaticamente pelo servidor a partir da tabela de contatos.

```json
{
  "to": { "contact_id": "ct_a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4" },
  "content": { "text": "Olá, tudo bem?" }
}
```

:::tip[Obtendo o contact_id]
O `contact_id` (formato `ct_{hex32}`) é retornado em webhooks de contato
(`contact.created`, `contact.name_changed`, `contact.picture_changed` e
`contact.first_messaged`) e no endpoint `GET /v1/numbers/{alias}/contacts`.
:::
