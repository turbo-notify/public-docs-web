Mídia (imagens, áudios, vídeos, documentos e figurinhas) é enviada
pelo mesmo endpoint `POST /v1/messages` usado para texto. Os campos de
mídia ficam dentro do objeto **aninhado `content`** — o tipo é inferido
automaticamente pelo campo âncora presente (`image_url`, `video_url`,
`audio_url`, `document_url` ou `sticker_url`).

:::caution[Implementação em progresso]
O contrato HTTP é final, mas o upload outbound de mídia para o
WhatsApp está em finalização (gateway neonize). Requests para os 5
tipos de mídia abaixo são aceitos pela API e geram `message_id`, mas
o worker pode retornar `message.send.failed` com `whatsapp_send_failed`
até o release que completa o gateway. Acompanhe o webhook
`message.sent` para confirmar o envio.
:::

## Tipos de mídia suportados

| Variante | Campo âncora | Formatos comuns | Tamanho máximo | `caption`? | `filename`? |
| -------- | ------------ | --------------- | :------------: | :--------: | :---------: |
| `image` | `image_url` | JPEG, PNG, WebP | 16 MB | ✓ | — |
| `video` | `video_url` | MP4 | 100 MB | ✓ | — |
| `audio` | `audio_url` | MP3, OGG, M4A | 16 MB | — | — |
| `document` | `document_url` | PDF, DOCX, XLSX, etc. | 100 MB | ✓ | ✓ |
| `sticker` | `sticker_url` | WebP animado | 500 KB | — | — |

`caption` **não é aceito** em `audio` e `sticker` — a API retorna
`422` se o campo for enviado nesses tipos.

## Modalidade — URL pública

Forneça uma URL HTTPS acessível publicamente. O Turbo Notify busca o
arquivo antes de entregar ao WhatsApp.

## Modalidade — objeto no seu bucket (BYO Storage)

Se você já possui o arquivo no seu BYO Object Storage, informe `s3_object_key`
em vez de `url`. O Turbo Notify acessa o arquivo diretamente usando as
credenciais que você configurou no dashboard.

:::caution[BYO Storage obrigatório]
O campo `s3_object_key` exige que o <DashboardLink path="/settings/integrations/storage">Object Storage</DashboardLink>
esteja configurado e ativo. Sem integração ativa, a requisição retorna
`412 Precondition Failed` com código `storage_required`.
:::

```json title="Exemplo — imagem por s3_object_key"
{
  "to": {"number": "+5511999999999"},
  "content": {
    "s3_object_key": "media/fotos/produto-42.jpg",
    "mime_type": "image/jpeg",
    "caption": "Foto do produto"
  }
}
```

:::note
Quando `s3_object_key` é usado sem `image_url` (ou equivalente de outro tipo), o Turbo Notify infere a variante de mídia a partir do `mime_type`. Forneça sempre `mime_type` nesse cenário.
:::

### Erro 412 — storage_required

Quando `s3_object_key` é informado mas nenhum Object Storage está configurado:

```json title="412 storage_required"
{
  "error": "storage_required",
  "message": "BYO Object Storage is required to use s3_object_key. Configure it in the Dashboard.",
  "hint": {
    "setup_url": "https://dashboard.turbonotify.com/settings/integrations/storage",
    "docs_url": "https://docs.turbonotify.com/general/byo-storage-setup/"
  }
}
```

## Esquema de campos (todos os tipos)

Os campos de mídia ficam dentro do objeto `content`. O campo âncora (ex.: `image_url`) determina a variante.

| Campo em `content` | Tipo | Obrigatório | Notas |
|---|---|---|---|
| `image_url` | URL | condicional | Campo âncora para imagens; URL pública HTTPS; exclusivo com `s3_object_key` |
| `video_url` | URL | condicional | Campo âncora para vídeos; URL pública HTTPS; exclusivo com `s3_object_key` |
| `audio_url` | URL | condicional | Campo âncora para áudios; URL pública HTTPS; exclusivo com `s3_object_key` |
| `document_url` | URL | condicional | Campo âncora para documentos; URL pública HTTPS; exclusivo com `s3_object_key` |
| `sticker_url` | URL | condicional | Campo âncora para figurinhas; URL pública HTTPS; exclusivo com `s3_object_key` |
| `s3_object_key` | string | condicional | Chave do objeto no seu BYO Storage; exclusivo com os campos `*_url`. Exige storage configurado. |
| `mime_type` | string | não | recomendado; o worker pode inferir do `Content-Type` da resposta |
| `caption` | string | parcial | aceito em `image`, `video`, `document`; **não aceito** em `audio` e `sticker` (retorna `422`) |
| `filename` | string | não | apenas em `document`; aparece como nome do anexo no chat |

## Resposta

```json title="response.json"
{
  "message_id": "msg_a1b2c3d4e5f60718293a4b5c6d7e8f90",
  "status": {
    "state": "pending",
    "at": "2026-04-27T10:00:05.123456+00:00"
  }
}
```

A confirmação real chega via webhook `message.sent`. Em caso de falha
(URL inacessível, formato não suportado, tamanho excedido) você recebe
`message.send.failed` com um objeto `error` (`{ code, message, hint }`) específico.

## Webhook outbound

Quando o envio é confirmado pelo WhatsApp, o webhook `message.sent`
carrega `content_type` e `preview` (mesmo shape de `message.received`):

```json title="webhook-message-sent.json"
{
  "id": "evt_abc123def456789012345678",
  "type": "message.sent",
  "organization_id": "org_a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4",
  "number_alias": "main",
  "created_at": "2026-04-27T10:00:08Z",
  "data": {
    "id": "msg_a1b2c3d4e5f60718293a4b5c6d7e8f90",
    "from": { "alias": "main", "number": "5511999990001" },
    "to":   { "number": "5511999999999" },
    "preview": "Foto do produto",
    "content_type": "image",
    "direction": "outbound",
    "channel": "whatsapp",
    "origin": "tn",
    "at": "2026-04-27T10:00:08Z"
  }
}
```

Para baixar o arquivo de uma mídia recebida, consulte
[`GET /v1/messages/{id}`](/messages/get/) — o body inclui `media.url`
com URL pré-assinada do seu BYO Object Storage (quando configurado).
