Mídia (imagens, áudios, vídeos, documentos e figurinhas) é enviada
pelo mesmo endpoint `POST /v1/messages` usado para texto. Os campos de
mídia ficam dentro do objeto **aninhado `content`**. O tipo é inferido
automaticamente pelo campo âncora presente (`image_url`, `video_url`,
`audio_url`, `document_url` ou `sticker_url`).

:::tip[Usando números extras?]
Para enviar mídia a partir de um número extra, use `/v1/numbers/{alias}/messages` onde
`{alias}` é o alias do seu número extra. [Saiba mais](/numbers/add/).
:::

## Tipos de mídia suportados

| Variante | Campo âncora | Formatos comuns | Tamanho máximo | `caption`? | `filename`? |
| -------- | ------------ | --------------- | :------------: | :--------: | :---------: |
| `image` | `image_url` | JPEG, PNG, WebP | 16 MB | ✓ | — |
| `video` | `video_url` | MP4 | 100 MB | ✓ | — |
| `audio` | `audio_url` | MP3, OGG, M4A | 16 MB | — | — |
| `document` | `document_url` | PDF, DOCX, XLSX, etc. | 100 MB | ✓ | ✓ |
| `sticker` | `sticker_url` | WebP animado, exatamente 512×512px | 500 KB | — | — |

`caption` **não é aceito** em `audio` e `sticker`. A API retorna
`422` se o campo for enviado nesses tipos.

## Modalidade: URL pública

Forneça uma URL HTTPS acessível publicamente. O Turbo Notify busca o
arquivo antes de entregar ao WhatsApp.

:::tip[Menções no caption]
O `caption` de imagem aceita tokens de menção `@<numero>` (por exemplo
`"caption": "Confere essa foto, @5511987650000?"`) com as mesmas regras do
`text` (detecção implícita, dígitos E.164 sem `+`, fail-open).
Veja [Menções (@mentions)](/messages/send/#menções-mentions).
:::

## Esquema de campos (todos os tipos)

Os campos de mídia ficam dentro do objeto `content`. O campo âncora (ex.: `image_url`) determina a variante. Todo envio de mídia é feito por URL pública; não existe modalidade de envio direto por chave de objeto do seu BYO Storage.

| Campo em `content` | Tipo | Obrigatório | Notas |
|---|---|---|---|
| `image_url` | URL | condicional | Campo âncora para imagens; URL pública HTTPS |
| `video_url` | URL | condicional | Campo âncora para vídeos; URL pública HTTPS |
| `audio_url` | URL | condicional | Campo âncora para áudios; URL pública HTTPS |
| `document_url` | URL | condicional | Campo âncora para documentos; URL pública HTTPS |
| `sticker_url` | URL | condicional | Campo âncora para figurinhas; URL pública HTTPS |
| `mime_type` | string | não | recomendado; o Turbo Notify pode inferir do `Content-Type` da resposta |
| `caption` | string | parcial | aceito em `image`, `video`, `document`; **não aceito** em `audio` e `sticker` (retorna `422`). Aceita tokens de [menção `@<numero>`](/messages/send/#menções-mentions), detecção implícita, mesmas regras do `text` |
| `filename` | string | não | apenas em `document`; aparece como nome do anexo no chat |

## Resposta

<ApiResponse
  status={202}
  body={{
    message_id: 'msg_a1b2c3d4e5f60718293a4b5c6d7e8f90',
    status: { state: 'pending', at: '2026-04-27T10:00:05Z' },
  }}
/>

A confirmação real chega via webhook `message.sent`. Em caso de falha
(URL inacessível, formato não suportado, tamanho excedido) você recebe
`message.send.failed` com um objeto `error` (`{ code, message, hint }`) específico.

## Webhook outbound

Quando o envio é confirmado pelo WhatsApp, o webhook `message.sent`
carrega `content_type` e `preview` (mesmo shape de `message.received`):

```json title="webhook-message-sent.json"
{
  "id": "evt_abc123def456789012345678",
  "type": "message.sent",
  "organization_id": "org_a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4",
  "number_alias": "main",
  "created_at": "2026-04-27T10:00:08Z",
  "data": {
    "id": "msg_a1b2c3d4e5f60718293a4b5c6d7e8f90",
    "from": { "alias": "main", "number": "5511999990001" },
    "to":   { "number": "5511999999999" },
    "preview": "Foto do produto",
    "content_type": "image",
    "direction": "outbound",
    "channel": "whatsapp",
    "origin": "tn",
    "at": "2026-04-27T10:00:08Z"
  }
}
```

Para baixar o arquivo de uma mídia recebida, consulte
[`GET /v1/numbers/{alias}/messages/{id}`](/messages/get/): os campos de mídia
aparecem **diretamente** no objeto específico do `content_type` (`image`, `video`,
`audio`, `document`, `sticker`), sem sub-objeto `media`. Com BYO Object Storage
configurado, esse objeto vem com `kind: "available"` e `url` contendo a URL
pré-assinada de download.
