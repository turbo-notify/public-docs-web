Ambas as operações agem sobre uma mensagem **já enviada** por você (outbound) — o `message_id` é o mesmo `msg_{hex32}` retornado pelo envio original ou visto em webhooks/polling. As duas retornam **202 Accepted** imediatamente; o resultado real chega de forma assíncrona via webhook.

Use `POST /v1/messages/{id}/edit` e `POST /v1/messages/{id}/delete` para o número principal. Para números extras, use `POST /v1/numbers/{alias}/messages/{id}/edit` e `.../delete`.

**Escopo obrigatório:** `messages:send`

## Editar mensagem

Substitui o texto de uma mensagem de texto já enviada (edição nativa do WhatsApp — o histórico da conversa mostra "editada").

      -H "Authorization: Bearer SUA_CHAVE" \
      -H "Content-Type: application/json" \
      -d '{
        "text": "Texto corrigido da mensagem."

### Corpo da requisição

| Campo | Tipo | Obrigatório | Notas |
|---|---|---|---|
| `text` | string | sim | 1–65.536 caracteres. Único campo aceito — corpo estrito (`extra=forbid`; qualquer outro campo retorna `422`). |

### Resposta (202)

<ApiResponse
  status={202}
  body={{
    message_id: 'msg_01993c5a1b24d3e9f01a2b3c4d5e6f70',
    status: { state: 'pending', at: '2026-06-01T10:05:01-03:00' },
  }}
/>

O resultado real chega via webhook `message.edited` (sucesso) ou
`message.edit.failed` (falha, com objeto `error`). Após a edição,
`GET /v1/numbers/{alias}/messages/{id}` já retorna o texto atualizado.

### Resposta (202)

<ApiResponse
  status={202}
  body={{
    message_id: 'msg_01993c5a1b24d3e9f01a2b3c4d5e6f70',
    status: { state: 'pending', at: '2026-06-01T10:06:01-03:00' },

/>

O resultado real chega via webhook `message.deleted` (sucesso) ou
`message.delete.failed` (falha, com objeto `error`).

Após uma exclusão bem-sucedida, `GET /v1/numbers/{alias}/messages/{id}` deixa
de retornar o texto/preview (campo vazio) tanto para quem apagou quanto para
todo destinatário da mensagem. Se a mensagem original era de mídia (imagem,
vídeo, áudio, documento ou figurinha), o bloco de mídia correspondente passa
a `{"kind": "unavailable", "reason": "deleted"}` em ambos os lados — a mídia
não fica mais acessível via URL assinada.

## Erros possíveis

Os dois endpoints compartilham o mesmo conjunto de erros:

| Status | Código de erro          | Descrição                                                     |
| :----: | ------------------------ | -------------------------------------------------------------- |
| `400`  | `message_not_editable`   | *(apenas edit)* A mensagem ainda não foi enviada, ou seu status atual (`failed`, por exemplo) não permite edição. |
| `400`  | `message_not_deletable`  | *(apenas delete)* A mensagem ainda não foi enviada, ou seu status atual não permite exclusão. |
| `403`  | `not_authorized`         | A chave de acesso está inválida ou ausente.                     |
| `403`  | `insufficient_scope`     | A chave de acesso não possui o escopo `messages:send` (resposta inclui `required_scope`). |
| `404`  | `number_not_found`       | O alias informado na URL não corresponde a nenhum número cadastrado. |
| `404`  | `message_not_found`      | O `message_id` não existe, não pertence ao organization, ou não pertence ao número identificado pelo alias na URL. |
| `422`  | `session_not_connected`  | O número que originalmente enviou a mensagem não tem uma sessão WhatsApp conectada no momento. |
| `500`  | `internal_error`         | Erro interno inesperado no servidor.                            |

Apenas mensagens outbound com status `sent`, `delivered` ou `read` podem ser
editadas ou deletadas — mensagens ainda `pending`, já `failed`, ou
mensagens inbound (recebidas), retornam `400`.
