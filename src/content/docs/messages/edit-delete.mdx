Ambas as operações agem sobre uma mensagem **já enviada** por você (outbound). O `message_id` é o mesmo `msg_{hex32}` retornado pelo envio original ou visto em webhooks/polling. As duas retornam **202 Accepted** imediatamente; o resultado real chega de forma assíncrona via webhook.

Use `POST /v1/messages/{id}/edit` e `POST /v1/messages/{id}/delete` para o número principal. Para números extras, use `POST /v1/numbers/{alias}/messages/{id}/edit` e `.../delete`.

**Escopo obrigatório:** `messages:send`

## Editar mensagem

Substitui o texto de uma mensagem de texto já enviada (edição nativa do WhatsApp: o histórico da conversa mostra "editada").

### Corpo da requisição

| Campo | Tipo | Obrigatório | Notas |
|---|---|---|---|
| `text` | string | sim | 1–65.536 caracteres. Único campo aceito: corpo estrito (qualquer outro campo retorna `422`). |

### Resposta (202)

<ApiResponse
  status={202}
  body={{
    message_id: 'msg_01993c5a1b24d3e9f01a2b3c4d5e6f70',
    status: { state: 'pending', at: '2026-06-01T13:05:01Z' },
  }}
/>

O resultado real chega via webhook `message.edited` (sucesso) ou
`message.edit.failed` (falha, com objeto `error`). Após a edição,
`GET /v1/numbers/{alias}/messages/{id}` já retorna o texto atualizado.

### Menções em edições

O novo `text` do edit também é varrido pela detecção implícita de tokens
`@<numero>`, as mesmas regras de [Menções (@mentions)](/messages/send/#menções-mentions).
A edição **substitui todo o conjunto de menções** da mensagem: o `mentions`
retornado por `GET /v1/numbers/{alias}/messages/{id}` (e o `data.mentions` do
webhook `message.edited`) passa a refletir só os tokens presentes no texto
**novo**. Uma edição que remove todos os `@<numero>` do texto original faz
`mentions` desaparecer da resposta.

### Resposta (202)

<ApiResponse
  status={202}
  body={{
    message_id: 'msg_01993c5a1b24d3e9f01a2b3c4d5e6f70',
    status: { state: 'pending', at: '2026-06-01T13:06:01Z' },

O resultado real chega via webhook `message.deleted` (sucesso) ou
`message.delete.failed` (falha, com objeto `error`).

Após uma exclusão bem-sucedida, `GET /v1/numbers/{alias}/messages/{id}` deixa
de retornar o conteúdo original tanto para quem apagou quanto para todo
destinatário da mensagem. O `content_type` da mensagem **não muda**: o que
muda é o conteúdo do campo estruturado correspondente:

| `content_type` original | Campo afetado | Valor após a exclusão |
| --- | --- | --- |
| `text` | `text` | `""` (string vazia) |
| `image` / `video` / `audio` / `document` / `sticker` | `image` / `video` / `audio` / `document` / `sticker` | `{"kind": "unavailable", "reason": "deleted"}`: a mídia não fica mais acessível via URL assinada |
| `location` | `location` | `{"kind": "unavailable", "reason": "deleted"}` |
| `calendar` | `calendar` | `{"kind": "unavailable", "reason": "deleted"}` |
| `contact` | `contact` | `{"kind": "unavailable", "reason": "deleted"}` |
| `interactive` | `interactive` | `{"kind": "unavailable", "reason": "deleted"}` |

O mesmo objeto `{"kind": "unavailable", "reason": "deleted"}` é usado em
todos os casos não-texto, inclusive para `location`/`calendar`/`contact`/
`interactive`, que não carregam mídia própria, para que o cliente tenha
**um único formato previsível** para "este conteúdo não está mais
disponível", em vez de precisar tratar cada `content_type` de forma
diferente.

## Erros possíveis

Os dois endpoints compartilham o mesmo conjunto de erros:

| Status | Código de erro          | Descrição                                                     |
| :----: | ------------------------ | -------------------------------------------------------------- |
| `400`  | `message_not_editable`   | *(apenas edit)* A mensagem é **inbound** (recebida de outra pessoa), foi enviada pelo próprio celular (`origin: "native"`), não é do tipo texto, ainda não foi enviada, já foi deletada, ou seu status atual (`failed`, por exemplo) não permite edição. |
| `400`  | `message_not_deletable`  | *(apenas delete)* A mensagem é **inbound** (recebida de outra pessoa), foi enviada pelo próprio celular (`origin: "native"`), ainda não foi enviada, já foi deletada, ou seu status atual não permite exclusão. |
| `403`  | `not_authorized`         | A chave de acesso está inválida ou ausente.                     |
| `403`  | `insufficient_scope`     | A chave de acesso não possui o escopo `messages:send` (resposta inclui `required_scope`). |
| `404`  | `number_not_found`       | O alias informado na URL não corresponde a nenhum número cadastrado. |
| `404`  | `not_found`              | A mensagem não foi encontrada, pertence a outra organização ou está fora da [janela de retenção de conteúdo](/messages/retention/) do plano: a janela **também** se aplica a editar e apagar, e os três casos devolvem a mesma resposta. |
| `404`  | `message_not_found`      | O `message_id` existe mas pertence a um número diferente do alias informado na URL. |
| `422`  | `session_not_connected`  | O número que originalmente enviou a mensagem não tem uma sessão WhatsApp conectada no momento. |
| `500`  | `internal_error`         | Erro interno inesperado no servidor.                            |

## Quais mensagens podem ser editadas ou deletadas

Três critérios, e os três precisam ser satisfeitos: qualquer um que falhe é
rejeitado **de forma síncrona**, com `400 message_not_editable` /
`400 message_not_deletable`, antes de qualquer round-trip com o WhatsApp:

1. **Enviada por este número, via esta API**: a mensagem precisa ter sido
   enviada pela API do Turbo Notify por este número (`direction: "outbound"`
   e `origin: "tn"`). Duas mensagens ficam de fora por este critério:
   - Mensagens **inbound** (recebidas): mensagens que um contato/participante
     enviou **para** você. Elas pertencem ao remetente, não a você, e o
     WhatsApp não permite que você edite ou revogue uma mensagem que não
     enviou.
   - Mensagens outbound digitadas **no próprio celular** (`origin: "native"`),
     enviadas fora da API, direto no aparelho. O worker da Turbo Notify não
     é o cliente que originou essa mensagem, então também não pode editá-la
     ou revogá-la.
2. **Tipo de conteúdo** *(apenas edit)*: o WhatsApp só suporta editar
   mensagens de **texto**. Editar uma mensagem de mídia (imagem, vídeo,
   áudio, documento, sticker) ou de outro tipo estruturado (localização,
   calendário, contato, interativa) falha com `400 message_not_editable`.
3. **Status**: apenas as mensagens que já estão em `sent`, `delivered` ou
   `read`, e que ainda não foram deletadas, são aceitas. Mensagens ainda
   `pending`, já `failed`, ou já deletadas retornam
   `400 message_not_editable` / `400 message_not_deletable`.
