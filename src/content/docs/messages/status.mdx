Após enviar uma mensagem, você pode consultar o status dela a qualquer momento pela API. O status reflete o andamento do processamento e entrega no WhatsApp.

## Tabela de status

| Status      | Descrição                                                                 |
| ----------- | ------------------------------------------------------------------------- |
| `pending`   | A mensagem foi recebida pelo Turbo Notify e aguarda processamento.        |
| `sent`      | A mensagem foi enviada ao WhatsApp com sucesso.                           |
| `delivered` | A mensagem foi entregue ao dispositivo do destinatário.                   |
| `read`      | A mensagem foi lida pelo destinatário.                                    |
| `failed`    | O envio falhou. Consulte o objeto `error` (`{code, message, hint}`) para detalhes. |

## Consultar status

Para consultar o status de uma mensagem, faça uma requisição `GET` informando o `message_id` retornado no envio.

## Detalhes da falha

Quando o status é `failed`, o objeto `error` carrega os detalhes. É **o mesmo
shape** do `data.error` dos webhooks `*.failed` (consistência evento ↔ recurso —
veja [Webhooks](/messages/webhook/) e [Recuperar mensagem](/messages/get/)):

| Campo          | Descrição                                                                 |
| -------------- | ------------------------------------------------------------------------- |
| `error.code`   | Código estável legível por máquina — faça branch neste valor (ex.: `whatsapp_unavailable`, `media_fetch_failed`, `blocked`). |
| `error.message`| Descrição legível da falha.                                               |
| `error.hint`   | `string \| null` — orientação acionável para corrigir, derivada do `code`. |

Status não-`failed` (`pending`/`sent`/`delivered`/`read`) não trazem o campo `error`.

## Erros possíveis

| Status | Código de erro   | Descrição                                            |
| :----: | ---------------- | ---------------------------------------------------- |
| `403`  | `not_authorized` | A chave de acesso está inválida ou ausente.          |
| `404`  | `not_found`      | A mensagem não foi encontrada ou já expirou.         |
| `500`  | `internal_error` | Erro interno inesperado no servidor.                 |
| `503`  | `service_unavailable` | O serviço está temporariamente indisponível.    |

## Retenção

As mensagens ficam disponíveis para consulta por um período limitado. Após esse prazo, o status não poderá mais ser consultado. Para detalhes, veja a documentação de [Retenção](/messages/retention/).

## Timestamp da transição de status

O momento de cada transição é exposto pelo campo unificado `at`, sempre relativo à última transição registrada:

- Em `GET /v1/messages/{id}` o campo `status.at` (e o `at` no nível raiz) marca quando o estado atual foi atingido.
- Em `GET /v1/messages/{id}/status` o objeto `status` carrega `{state, at}`.
- Nos eventos `message.sent`, `message.delivered` e `message.read` (webhook e polling via `GET /v1/events`) o instante da transição vem em `data.at` — o mesmo nome de campo em todos os eventos `message.*`.

## Atualizações em tempo real

Para receber atualizações automáticas sobre o status das mensagens sem precisar consultar a API repetidamente, configure um webhook. Veja como em [Respostas e Webhook](/messages/webhook/).
