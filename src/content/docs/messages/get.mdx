**Escopo obrigatório:** `messages:read`

## Campos da resposta

`from` e `to` são objetos com forma direção-aware — o mesmo shape usado nos webhooks. A linha Turbo Notify participante é identificada pelo `number_alias`; resolva seu número/contato via `GET /v1/numbers/{alias}`.

| Campo | Tipo | Descrição |
| ----- | ---- | --------- |
| `id` | string | Identificador público da mensagem (`msg_` + 32 hex) |
| `organization_id` | string | Identificador público da sua organização (`org_{hex32}`). Sempre presente. |
| `number_alias` | string | Handle do número Turbo Notify ao qual a mensagem pertence — `"main"` ou o alias de um número extra. Resolva seu número/contato via `GET /v1/numbers/{alias}`. |
| `from` | object | Remetente — shape direção-aware |
| `to` | object | Destinatário — shape direção-aware |
| `preview` | string | Permanente — recorte grapheme-aware do conteúdo |
| _campo específico_ | object\|string | Conteúdo completo nomeado pelo `content_type` (`text`, `image`, …). Veja a tabela abaixo. |
| `content_type` | string | `text`, `image`, `audio`, `video`, `document`, `sticker`, `location`, `calendar` |
| `direction` | string | `outbound` (enviada) ou `inbound` (recebida) |
| `channel` | string | Sempre `"whatsapp"` |
| `origin` | string | `"tn"` (envio via Turbo Notify API) ou `"native"` (digitada no celular). Sempre presente. |
| `at` | string | ISO 8601 com offset — momento **estável de ocorrência** da mensagem no WhatsApp (outbound: o momento real de envio; inbound: o momento de recebimento). **Não muda** conforme a mensagem avança `sent → delivered → read` — para o momento da entrega/leitura atual use `status.at`. |
| `status` | object | `{state, at}` — estado atual de entrega e o `status.at` correspondente. Diferente do `at` raiz, o `status.at` **avança** a cada transição (move para `delivered`, depois `read`). |

### Campos por `content_type`

Além dos campos comuns acima, cada `content_type` expõe um campo específico com o conteúdo completo:

| `content_type` | Campo específico | Descrição |
|---|---|---|
| `text` | `text` | Texto completo da mensagem |
| `image` | `image` | Objeto com `caption?` e campos de mídia (`kind`, `url?`, `expires_at?`, …) diretamente |
| `video` | `video` | Objeto com `caption?` e campos de mídia |
| `audio` | `audio` | Objeto com campos de mídia e `transcription?` (Whisper, se configurado) |
| `document` | `document` | Objeto com `filename?`, `caption?` e campos de mídia |
| `sticker` | `sticker` | Objeto com campos de mídia |
| `location` | `location` | Objeto com `latitude`, `longitude`, `name?`, `address?`, `url?`, `is_live`, `thumbnail_b64?` |
| `calendar` | `calendar` | Objeto com `name`, `description?`, `start_at?`, `end_at?`, `join_link?`, `location?`, `has_reminder`, `reminder_offset_sec?` |

Para mensagens `replied` (citações):

| Campo | Tipo | Descrição |
|---|---|---|
| `replied` | object | `{message_id: string, preview: string}` — referência e preview da mensagem citada |

Para mensagens `reacted`:

| Campo | Tipo | Descrição |
|---|---|---|
| `text` | string | O emoji da reação (ex.: `"👍"`) ou `""` para remoção |

## Campos de mídia

Os campos de mídia aparecem **diretamente** no objeto específico (`image`, `video`, `audio`, `document`, `sticker`) — sem sub-objeto `media`. É uma **união discriminada** pelo campo `kind`:

### `kind: "available"`

Mídia disponível para download. Requer <DashboardLink path="/settings/integrations/storage">Object Storage configurado</DashboardLink>.

| Campo | Tipo | Descrição |
| ----- | ---- | --------- |
| `kind` | string | `"available"` |
| `url` | string | URL pré-assinada de download |
| `expires_at` | `string \| null` | Timestamp de expiração do acesso à mídia. Consulte a mensagem novamente para obter uma nova URL após a expiração. |
| `mime_type` | `string \| null` | Tipo MIME do arquivo (ex: `image/jpeg`, `application/pdf`) |
| `size_bytes` | `integer \| null` | Tamanho do arquivo em bytes |

### `kind: "pending"`

Upload da mídia para o seu bucket ainda está em andamento. Aguarde alguns segundos e consulte novamente.

| Campo | Tipo | Descrição |
| ----- | ---- | --------- |
| `kind` | string | `"pending"` |
| `mime_type` | `string \| null` | Tipo MIME detectado |
| `size_bytes` | `integer \| null` | Tamanho do arquivo em bytes |

### `kind: "unavailable"`

Mídia não está disponível. O campo `reason` indica a causa.

| Campo | Tipo | Descrição |
| ----- | ---- | --------- |
| `kind` | string | `"unavailable"` |
| `reason` | string | `no_storage` — nenhum Object Storage configurado; `storage_circuit_open` — circuit breaker aberto no recebimento; `upload_failed` — storage saudável, mas este item não pôde ser persistido. O motivo é gravado no recebimento e lido literalmente. |
| `mime_type` | `string \| null` | Tipo MIME detectado |
| `size_bytes` | `integer \| null` | Tamanho do arquivo em bytes |
| `setup_hint` | `object \| null` | Presente quando `reason` é `no_storage` ou `storage_circuit_open`. Contém `setup_url`, `docs_url` e `message`. |

## Status da mensagem

O campo `status` contém o estado atual de entrega:

| Campo | Tipo | Descrição |
| ----- | ---- | --------- |
| `state` | string | Estado atual: `sent`, `delivered`, `read`, `received`, `failed` |
| `at` | string | ISO 8601 — timestamp do **estado atual de entrega**; **avança** a cada transição (`sent → delivered → read`). Não confundir com o `at` no nível raiz, que é o momento estável de ocorrência da mensagem. |
| `error` | `object \| null` | Erro estruturado da falha — presente apenas quando `state: "failed"`, `null` caso contrário. **Mesmo shape** do `data.error` dos webhooks `*.failed`. |
| `error.code` | `string` | Código estável legível por máquina — faça branch neste valor. |
| `error.message` | `string` | Descrição legível da falha. |
| `error.hint` | `string \| null` | Orientação acionável, derivada do `code`. |

## Sobre `preview`

O campo `preview` é **permanente** — nunca é removido pelo ciclo de retenção (LGPD). Contém um recorte grapheme-aware do conteúdo:
- Para `text`: primeiros ~50 caracteres do texto.
- Para `location`: texto humanizado sem colchetes (ex: `Av. Paulista, Sao Paulo, SP`).
- Para `calendar`: resumo sem colchetes (ex: `Sprint Planning — qui, 1 jun 2026 14:00`).
- Para mídia: a legenda (quando disponível) ou o label do tipo em inglês (`[Image]`, `[Video]`, `[Audio]`, `[Document]`, `[Sticker]`).
- Para reações: o emoji ou `""` para remoção.

O campo do conteúdo completo (`text`, `image`, `location`, etc.) pode ser `null` após o período de retenção — `preview` é o único campo que garante acesso ao conteúdo em qualquer momento.

## Sobre `kind`

Para receber mídia inbound com `kind: "available"`, configure a <DashboardLink path="/settings/integrations/storage">integração de Object Storage</DashboardLink> no dashboard. Sem essa configuração, o Turbo Notify não tem onde armazenar a mídia e retorna `kind: "unavailable"` com `reason: "no_storage"`.

Quando o Object Storage está configurado, o Turbo Notify copia automaticamente cada mídia recebida para o seu bucket e retorna uma URL pré-assinada com validade configurável. O acesso à mídia expira conforme o `expires_at` — você pode obter uma nova URL consultando a mensagem novamente.

## Erros possíveis

| Status | Código de erro | Descrição |
| :----: | -------------- | --------- |
| `400` | `invalid_message_id` | O identificador não corresponde ao formato `msg_` + 32 hex. |
| `403` | `not_authorized` | A chave de acesso está inválida, ausente ou sem o escopo `messages:read`. |
| `404` | `not_found` | Mensagem não encontrada ou pertence a outro organization. |
| `429` | `rate_limit_exceeded` | Limite de requisições ultrapassado. |
| `500` | `internal_error` | Erro interno inesperado no servidor. |
