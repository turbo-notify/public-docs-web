---
title: Eventos de ciclo de vida de grupo
description: 10 webhooks que o Turbo Notify emite quando o estado de um grupo WhatsApp muda.
---

O Turbo Notify emite 10 webhooks adicionais quando seu número entra/sai
de grupos ou quando o estado de um grupo muda. Todos seguem o
naming `group.{ação}` com verbo no past-participle (consistente com
`contact.name_changed`).

| Tipo | Quando |
|---|---|
| `group.joined` | Seu número foi adicionado a um grupo (ou criou um) |
| `group.left` | Seu número foi removido, saiu, ou o grupo foi dissolvido |
| `group.name_changed` | O nome do grupo mudou |
| `group.description_changed` | A descrição (topic) do grupo mudou |
| `group.picture_changed` | A foto do grupo mudou |
| `group.settings_changed` | Uma configuração mudou (announce-only, locked, ephemeral, parent) |
| `group.participants_added` | Outros participantes foram adicionados ao grupo |
| `group.participants_removed` | Outros participantes foram removidos |
| `group.participants_promoted` | Participantes foram promovidos a admin |
| `group.participants_demoted` | Admins foram rebaixados |

Desde 2026-06-06 o `data` de cada evento `group.*` espelha o `data` de
`message.*`: o id público do grupo vem **plano no topo** como `id`
(`grp_{hex32}`) + `name` (antes era o sibling aninhado `group: {id, name}`), mais
o tail de coerência `direction: "inbound"` (grupos são observados pelo canal do
WhatsApp), `channel: "whatsapp"` e `origin: "tn"`.

> Os objetos `participants[]` e `*_by` continuam sendo **parties**
> (`{contact_id, name, number}`) — referenciam contatos da contraparte, não o
> sujeito do evento, então mantêm a chave `contact_id`.

> **Campo `at`.** Os eventos que refletem uma ação real no WhatsApp —
> `group.name_changed`, `group.description_changed`, `group.settings_changed`,
> `group.participants_added`, `group.participants_removed`,
> `group.participants_promoted`, `group.participants_demoted` e `group.left` —
> carregam `data.at` com o **momento genuíno da ação no WhatsApp** (distinto do
> `created_at` do envelope). Já `group.joined` e `group.picture_changed`
> **não** carregam `at`: são descobertas de snapshot/foto sem um momento de ação
> WhatsApp único — apenas o `created_at` do envelope se aplica.

## Exemplos

> O primeiro exemplo (`group.joined`) mostra o **envelope completo**. Por
> brevidade, os demais exibem apenas `type` + `data` — o envelope é idêntico:
> todo evento `group.*` carrega `number_alias` (o handle do número/"inbox" dono
> do grupo — grupos têm `number_id` NOT NULL) **imediatamente abaixo de
> `organization_id`**, junto com `id`, `created_at`.

### `group.joined`

```json
{
  "id": "evt_...",
  "type": "group.joined",
  "organization_id": "org_a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4",
  "number_alias": "support",
  "created_at": "2026-05-25T10:00:00Z",
  "data": {
    "id": "grp_9f6f0b37c98043e5835822eeae550e77",
    "name": "Grupo A",
    "joined_by": "5511999999999",
    "creation": false,
    "initial_participants_count": 7,
    "direction": "inbound",
    "channel": "whatsapp",
    "origin": "tn"
  }
}
```

- `id`/`name` são o id público (`grp_{hex32}`) e o snapshot de nome do grupo (o sujeito do evento).
- `group.joined` **não** carrega `data.at` — é uma descoberta de snapshot, não uma ação WhatsApp com momento próprio; use o `created_at` do envelope.
- `joined_by` é o número (digits-only) do admin que adicionou seu número, ou `null` quando o evento foi originado por sua própria criação do grupo (`creation=true`).

### `group.left`

```json
{
  "type": "group.left",
  "data": {
    "id": "grp_...",
    "name": "Grupo A",
    "removed_by": "5511999999999",
    "reason": "removed",
    "direction": "inbound",
    "channel": "whatsapp",
    "origin": "tn",
    "at": "2026-05-25T10:01:00Z"
  }
}
```

`reason` é informacional: `removed` (admin kicked), `left` (você saiu),
`deleted` (grupo dissolvido).

### `group.name_changed`

```json
{
  "type": "group.name_changed",
  "data": {
    "id": "grp_...",
    "name": "Grupo A 2.0",
    "old_name": "Grupo A",
    "changed_by": "5511999999999",
    "direction": "inbound",
    "channel": "whatsapp",
    "origin": "tn",
    "at": "2026-05-25T10:02:00Z"
  }
}
```

`name` é o nome **novo/atual** do grupo; `old_name` é o nome anterior. Não há
campo `new_name` — `name` já carrega o nome novo (mesma forma de
`contact.name_changed`).

### `group.description_changed`

```json
{
  "type": "group.description_changed",
  "data": {
    "id": "grp_...",
    "name": "Grupo A 2.0",
    "old_description": "...",
    "new_description": "...",
    "changed_by": "5511999999999",
    "direction": "inbound",
    "channel": "whatsapp",
    "origin": "tn",
    "at": "2026-05-25T10:03:00Z"
  }
}
```

### `group.picture_changed`

Emitido **apenas** quando uma foto de grupo real chega ao seu BYO Storage
(estado `organization_storage`). O bloco `picture` segue o mesmo ciclo de vida da mídia
de mensagem: `kind: "available"` com uma URL **pré-assinada e com validade
limitada** (`url_expires_at`, ~15 min) do seu bucket — nunca uma URL do WhatsApp.
Re-baixe a foto via o endpoint GET quando a URL expirar.

```json
{
  "type": "group.picture_changed",
  "data": {
    "id": "grp_...",
    "name": "Grupo A 2.0",
    "picture": {
      "kind": "available",
      "url": "https://<bucket>.r2.cloudflarestorage.com/groups/.../picture.jpg?...",
      "url_expires_at": "2026-05-25T10:19:00Z",
      "hash": "abc123...",
      "fetched_at": "2026-05-25T10:04:00Z"
    },
    "changed_by": "5511999999999",
    "direction": "inbound",
    "channel": "whatsapp",
    "origin": "tn"
  }
}
```

`group.picture_changed` **não** carrega `data.at` — é uma descoberta de foto
(snapshot) sem um momento de ação WhatsApp único; o `picture.fetched_at`
indica quando a foto foi baixada, e o `created_at` do envelope quando o evento
foi emitido.

Guarde o `picture.hash` para detectar mudanças efetivas e re-baixar a foto
antes que a URL pré-assinada expire (`url_expires_at`). Para ler a foto sob
demanda use [`GET /v1/numbers/{alias}/groups/{group_id}/picture`](/groups/picture/),
onde `{alias}` é o `number_alias` do envelope deste evento (a linha TN que
participa do grupo).

> **Pré-requisito: BYO Storage.** Este evento só dispara quando você tem uma
> integração de Object Storage habilitada — o Turbo Notify não serve a CDN do
> WhatsApp diretamente. Sem storage, a foto fica `unavailable` e nenhum
> `group.picture_changed` é emitido. Configure em
> [BYO Storage Setup](/general/byo-storage-setup/).

<a id="groups-picture-becomes-available"></a>

> **A foto fica disponível depois.** Se um grupo foi observado enquanto o
> storage estava ausente (ou o grupo ainda não tinha foto) e uma foto chega
> ao BYO Storage mais tarde, o Turbo Notify emite o `group.picture_changed`
> automaticamente assim que a foto é enviada ao seu bucket — você não precisa
> re-sincronizar nada.

### `group.settings_changed`

Um evento por setting que mudou (o WhatsApp pode emitir múltiplos
changes simultâneos; cada um vira um evento).

```json
{
  "type": "group.settings_changed",
  "data": {
    "id": "grp_...",
    "name": "Grupo A 2.0",
    "setting": "announce",
    "old_value": false,
    "new_value": true,
    "changed_by": "5511999999999",
    "direction": "inbound",
    "channel": "whatsapp",
    "origin": "tn",
    "at": "2026-05-25T10:05:00Z"
  }
}
```

`setting`: `announce` (apenas admins postam) | `locked` (apenas admins
editam info) | `ephemeral` (timer em segundos para disappearing messages)
| `parent` (group community parent).

### `group.participants_added`

Um único webhook por operação batch — todos os adicionados juntos.

```json
{
  "type": "group.participants_added",
  "data": {
    "id": "grp_...",
    "name": "Grupo A 2.0",
    "participants": [
      { "contact_id": "ct_...", "number": "5511555555555" },
      { "name": "Carlos", "number": "5511444444444" }
    ],
    "added_by": {
      "contact_id": "ct_...",
      "name": "Admin",
      "number": "5511999999999"
    },
    "direction": "inbound",
    "channel": "whatsapp",
    "origin": "tn",
    "at": "2026-05-25T10:06:00Z"
  }
}
```

- `participants[]` lista quem foi adicionado.
- `added_by` é o admin que executou a ação. Pode ser `null` se a
  resolução do JID falhou.
- `contact_id` é populado quando você já tinha o participante como
  contato (TN não cria novos contatos para participantes vistos via
  ciclo de vida — proteção LGPD + quota).

### `group.participants_removed`

Mesma forma de `added`, com `removed_by` no lugar de `added_by`.

### `group.participants_promoted`

Mesma forma, `promoted_by` em vez de `added_by`. Não muda o
participants_count do grupo.

### `group.participants_demoted`

Mesma forma, `demoted_by`. Não muda o participants_count.

## Coalescência

Quando o WhatsApp envia um payload "fat" com múltiplas mudanças
simultâneas (ex: nome + descrição + 5 adições no mesmo update),
o Turbo Notify emite **um webhook por mudança lógica** — permitindo
que sua subscription filtre pelo tipo desejado sem precisar parsear
um envelope polimórfico.

## Idempotência

Cada evento de ciclo de vida é entregue com um header `Nats-Msg-Id`
derivado de `(organization_id, group_id, concern, unix_ms)`. Replays do
JetStream colapsam dentro de uma janela curta — se você processou
o evento `id` uma vez, ignore qualquer reentrega do mesmo `id`.
