Disponível desde 2026-05-24 (inbound); envio disponível desde 2026-05-25.
O Turbo Notify reconhece grupos do WhatsApp como entidades de primeira
classe — mensagens recebidas em grupo trazem o contexto da conversa, e
o envio para grupos usa o identificador público `grp_{hex32}`.

## Conceitos

### Identificador público `grp_`

Toda referência pública a um grupo usa o formato `grp_` + 32 caracteres
hexadecimais, derivado do UUID interno do registro em
`tn_whatsapp.groups`. Mirror dos prefixos de outras entidades públicas
(`msg_`, `ct_`, `req_`, `evt_`).

> O identificador do WhatsApp (`120363xxxxx@g.us`) **nunca** é exposto
> em respostas, webhooks ou polling — apenas o `grp_{hex32}` da TN.

### Campo `to` polimórfico

O campo `to` discrimina por presença de chave — sem campo `kind` ou `type`:

- **1:1** → `to: { "number": "+55..." }` — destinatário pessoa.
- **Grupo** → `to: { "group_id": "grp_..." }` — destinatário grupo.
- **Por contact** → `to: { "contact_id": "ct_..." }` — resolve o telefone a partir do registro TN Contact.

A mesma regra vale para os payloads de webhook e polling: quando
`to.group_id` está presente, o destinatário lógico é o grupo.
Mensagens 1:1 preservam o shape pré-existente byte-idêntico.

### Campo `from` sempre é pessoa

Grupos não falam — participantes falam dentro de grupos. Portanto:

- Inbound: `from` é o participante que enviou a mensagem no grupo.
- Outbound: `from` é o número Turbo Notify que enviou a mensagem.

Em nenhum cenário `from` carrega um `group_id`.

### Campo `inbox` (mensagens de grupo)

O campo `inbox` é um sibling top-level, presente **sempre** (em todas as
mensagens — 1:1 e grupo, inbound e outbound). Em mensagens de grupo ele
identifica o número Turbo Notify que participa do grupo — o telefone
(`number`) e o alias (`alias`) da linha tenant-side.

```jsonc
// Inbound de grupo
{
  "inbox":  { "alias": "main", "number": "5511973117056" },
  "from":   { "contact_id": "ct_...", "name": "Cleverson", "number": "5571999258283" },
  "to":     { "group_id": "grp_e442553a56b14e2695f6acfd7d651b1a", "name": "TNT" }
}

// Outbound para grupo
{
  "inbox":  { "alias": "main", "number": "5511973117056" },
  "from":   { "name": "Turbo Notify", "alias": "main", "number": "5511973117056" },
  "to":     { "group_id": "grp_e442553a56b14e2695f6acfd7d651b1a", "name": "TNT" }
}
```

Para detectar mensagens de grupo, verifique a presença de `to.group_id`:

```js
const isGroup = "group_id" in data.to;
```

## Recebendo mensagens de grupo

Cada mensagem inbound proveniente de um grupo é entregue como
[`message.received`](/messages/webhook/#exemplo--messagereceived-grupo)
no webhook + polling. `from` é o participante que enviou; `to` traz o
`group_id` e o snapshot do nome do grupo; `inbox` identifica a linha
Turbo Notify que participa do grupo.

## Enviando para grupo

Para enviar a um grupo no `POST /v1/messages`, o campo `to` assume a
forma de objeto `{ "group_id": "grp_..." }`. O corpo é plano: os campos
de conteúdo (`content_type` + payload) ficam no nível raiz, igual ao 1:1.

O Turbo Notify resolve o `grp_{hex32}` para o JID interno do WhatsApp e
roteia a mensagem para o grupo usando a linha principal (ou extra, se
configurada). Para 1:1, o campo `to` é um objeto `{ "number": "+5511999999999" }`.

## Quota e rate-limit

Um envio para grupo conta como **1 destinatário** no rate-limit diário —
independente de quantos participantes o grupo tenha. A quota de
contatos (`contact.*`) **não** é afetada por envios para grupos: a
ADR 2026-05-25 fixa que grupos nunca materializam contatos.

## Ciclo de vida de grupo

O Turbo Notify emite 10 webhooks adicionais quando o estado do grupo
muda. Consulte [eventos de ciclo de vida de grupo](/groups/lifecycle-events/) para
o catálogo completo.
