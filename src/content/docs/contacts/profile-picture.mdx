Retorna a foto de perfil do contato via 302 redirect. O destino do redirect depende do estado de armazenamento (`picture_storage`).

> O 302 para `organization_storage` aponta para uma URL **pré-assinada** do seu BYO Storage (nunca a object key crua). Uma foto marcada como `unavailable` enquanto o storage estava ausente é **reavaliada** e enviada assim que você habilita o BYO Storage — o webhook [`contact.picture_changed`](/webhooks/contact-events/#exemplo-contactpicture_changed) é então emitido.

## Endpoint

```http
GET /v1/contacts/{contact_id}/profile-picture
```

**Scope:** `contacts:read`.

Para números extras: `GET /v1/numbers/{alias}/contacts/{contact_id}/profile-picture`, onde `{alias}` é o `number_alias` do envelope do evento de contato.

## Comportamento por `picture_storage`

| Estado | Resposta |
| ------ | -------- |
| `organization_storage` | 302 com URL pré-assinada do BYO Storage (R2/S3/Supabase) |
| `pending_upload` | 404 `contact_picture_unavailable` (upload ainda em andamento) |
| `upload_failed` | 404 `contact_picture_unavailable` (a tentativa de upload deste ciclo falhou; **não há retry imediato**). Diferente da mídia de mensagem — que é terminal — a foto é **re-resolvida na próxima interação do contato** (inbound/outbound), de forma session-affine; uma falha de upload pode se recuperar em uma interação futura se o storage estiver saudável. |
| `unavailable` | 404 `contact_picture_unavailable` |

## Modo proxy (opt-in)

Organizations com modo proxy habilitado recebem 200 com bytes inline (o backend faz o GET e devolve). Útil para evitar expor URLs do WhatsApp a clientes finais. **Aumenta o custo de banda** do organization — desabilitado por padrão.

Configuração: `dashboard → BYO Storage → Profile Picture Proxy = on`.

## Exemplo

```bash
curl -I "https://api.turbonotify.com/v1/contacts/ct_.../profile-picture" \
  -H "Authorization: Bearer $TURBO_API_KEY"

HTTP/1.1 302 Found
Location: https://<bucket>.r2.cloudflarestorage.com/...
Cache-Control: private, max-age=300
```

## Resposta de erro

<ApiResponse status={404}>
```json
{
  "error": "contact_picture_unavailable",
  "details": {
    "contact_id": "ct_...",
    "reason": "no_storage",
    "setup_hint": {
      "setup_url": "https://dashboard.turbonotify.com/storage",
      "docs_url": "https://docs.turbonotify.com/general/byo-storage-setup/",
      "message": "Configure object storage to serve contact pictures."
    }
  }
}
```
</ApiResponse>

O campo `reason` discrimina a causa: `no_storage` (sem storage configurado), `storage_circuit_open` (circuit breaker aberto), `upload_failed` (falha de upload neste ciclo — pode se recuperar na próxima interação do contato, ver tabela acima) ou `peer_has_none` (o contato/grupo não tem foto). O `setup_hint` acompanha apenas `no_storage` e `storage_circuit_open` — para `upload_failed` e `peer_has_none` ele é omitido.

## Cache

- Redirects são cacheados por `300s` (HTTP `Cache-Control: private, max-age=300`).
- URLs do BYO Storage têm validade interna do seu provider (R2: 1h por padrão).
