Retorna a foto de perfil do contato via 302 redirect. O destino do redirect depende do estado de armazenamento (`picture_storage`).

## Endpoint

```http
GET /v1/contacts/{contact_id}/profile-picture
```

**Scope:** `contacts:read`.

## Comportamento por `picture_storage`

| Estado | Resposta |
| ------ | -------- |
| `tenant_storage` | 302 com URL pré-assinada do BYO Storage (R2/S3/Supabase) |
| `whatsapp_direct` | 302 com URL direta do WhatsApp (pode expirar em ~24h) |
| `pending_upload` | 302 com URL do WhatsApp (fallback enquanto upload está em fila) |
| `upload_failed` | 302 com URL do WhatsApp (fallback enquanto retry está em curso) |
| `unavailable` | 404 `contact_picture_unavailable` |

## Modo proxy (opt-in)

Tenants com modo proxy habilitado recebem 200 com bytes inline (o backend faz o GET e devolve). Útil para evitar expor URLs do WhatsApp a clientes finais. **Aumenta o custo de banda** do tenant — desabilitado por padrão.

Configuração: `dashboard → BYO Storage → Profile Picture Proxy = on`.

## Exemplo

```bash
curl -I "https://api.turbonotify.com/v1/contacts/ct_.../profile-picture" \
  -H "Authorization: Bearer $TURBO_API_KEY"

HTTP/1.1 302 Found
Location: https://<bucket>.r2.cloudflarestorage.com/...
Cache-Control: max-age=60
```

## Resposta de erro

<ApiResponse status={404}>
```json
{
  "error": "contact_picture_unavailable",
  "details": {"contact_id": "ct_..."}
}
```
</ApiResponse>

## Cache

- Redirects são cacheados por `60s` (HTTP `Cache-Control: max-age=60`).
- URLs do BYO Storage têm validade interna do seu provider (R2: 1h por padrão).
