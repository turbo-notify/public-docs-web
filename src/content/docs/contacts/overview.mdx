Um **TN Contact** é um registro de observabilidade passiva que o Turbo Notify cria automaticamente a partir do tráfego de mensagens entre o número do organization e contatos externos. Não é um CRM. Não há sincronização de agenda. Não há endpoints de criação ou exclusão manual.

Contatos são escopados por número. Para o **número principal**, use as rotas planas (`/v1/contacts`, `/v1/contacts/{id}`, `/v1/contacts/quota`, etc.) ou a forma aninhada com o alias `main` (`/v1/numbers/main/contacts`, `/v1/numbers/main/contacts/{id}`, etc.) — ambas são equivalentes. Para **números extras**, use a forma aninhada `/v1/numbers/{alias}/contacts`. O mesmo telefone alcançado por dois números diferentes gera dois contatos distintos.

## Conceito

| Aspecto | Comportamento |
| ------- | ------------- |
| Origem | Mensagens (`inbound` ou `outbound`) ou número próprio (`self`) |
| Criação | Automática na primeira observação `(organization, telefone)` |
| Identificador | `ct_{hex32}` — public ID estável |
| Escopo | Organization-scoped (mesmo telefone em organizations distintos = contatos distintos) |
| Endurance | Sem TTL; persiste após `deleted_at` (soft delete histórico) |

## Ciclo de vida

```
[Inbound] message.received ────────┐
                                   ▼
[Outbound] POST /v1/numbers/{alias}/messages ──► TN Contact created ──► Enrichment (name, picture)
                                   ▲                                ▼
[Self] session.connected ──────────┘                     Webhook: contact.created
```

1. **Discovery** — primeira mensagem `(organization, phone)` cria o `Contact` com `source` apropriado.
2. **Enrichment** — pipeline assíncrono enriquece com `name`, `profile_picture`. Falhas são fail-open: o contato existe mesmo sem enriquecimento.
3. **Quota** — cada contato distinto **contactado via Turbo Notify** dentro do **ciclo de faturamento avaliado** da organização (`cycle_start` até `cycle_end`, não mais uma janela rolling de 30 dias — ADR 2026-07-04) consome um slot da quota de contatos do ciclo — **novo ou recorrente**. Re-mensagear alguém já contado neste ciclo consome um slot novamente; a quota só reseta em `resets_at` (fim do ciclo), nunca antes.

## Tier de quota

| Tier | Contatos distintos/ciclo | Mensagens/ciclo |
| ---- | ------------------------:| ----------------:|
| free     | 100      | 1.000      |
| solo     | 1.000    | 10.000     |
| business | 5.000    | 50.000     |
| custom   | 50.000+  | 500.000+   |

A razão 10:1 (mensagens/contato) reflete o uso médio em produção. Ambas as
quotas são **por número** (cada número da organização tem sua própria
franquia). Customizações por organization via `plan_overrides`, aplicadas
por número.

## Origens (source)

- `inbound` — primeira mensagem recebida desse telefone.
- `outbound` — primeira mensagem enviada para esse telefone.
- `self` — número controlado pelo organization (primário ou extra). Flag `is_self=TRUE`.

## Fora de escopo

- Não há `POST /v1/numbers/{alias}/contacts` — contatos são derivados de tráfego.
- Não há `DELETE /v1/numbers/{alias}/contacts/{id}` — use soft delete via dashboard.
- Não há sincronização de agenda do WhatsApp.
