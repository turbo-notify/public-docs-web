Retorna o payload completo de um contato, incluindo telefone e metadados da foto de perfil.

## Endpoint

```http
GET /v1/contacts/{contact_id}
```

Para números extras: `GET /v1/numbers/{alias}/contacts/{contact_id}`

**Escopo obrigatório:** `contacts:read`.

## Path

| Parâmetro | Tipo | Formato |
| --------- | ---- | ------- |
| `contact_id` | string | `ct_{hex32}`: regex `^ct_[0-9a-f]{32}$` |

## Resposta (200)

<ApiResponse
  status={200}
  body={{
    id: 'ct_a1b2c3d4e5f6789012345678901234ab',
    number_alias: 'main',
    phone_number: '+5571999294756',
    name: 'João Silva',
    is_self: false,
    first_messaged_at: '2026-05-10T13:25:00Z',
    last_interaction_at: '2026-05-10T13:42:00Z',
    verified_on_whatsapp_at: '2026-05-10T13:25:00Z',
    picture: {
      kind: 'available',
      url: 'https://cdn.example.com/contacts/ct_a1b2.jpg',
      url_expires_at: '2026-05-10T14:25:00Z',
      hash: 'a3f1c9...',
      fetched_at: '2026-05-10T13:25:00Z',
    },
    created_at: '2026-05-10T13:25:00Z',
    updated_at: '2026-05-10T13:42:00Z',
  }}
/>

O `number_alias` (logo após `id`) identifica o número do Turbo Notify a que
este contato pertence: `"main"` ou o alias de um número extra (o mesmo
telefone alcançado por dois números diferentes gera dois contatos distintos). O
`phone_number` é o **E.164 completo** (sem máscara), o mesmo número já
exposto em `message.from`/`message.to`. O campo `name` é o
push name do contato no WhatsApp (coerente com o triplo `{id, name, number}`
dos eventos `contact.*`). `picture` é uma união discriminada por `kind`
(`available` | `unavailable`), espelhando o bloco de mídia dos
eventos; quando `kind` é `available`, o próprio bloco carrega `fetched_at`.
O valor `pending` só aparece em payloads de webhook: este endpoint de
leitura nunca o retorna.

## Erros

- `404 contact_not_found`: ID inválido ou pertencente a outra organização.

Veja a [referência de erros](/contacts/errors/).
