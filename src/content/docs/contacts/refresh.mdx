Solicita o reenriquecimento de um contato sob demanda (name, foto). É um **system trigger** — não é CRUD. Retorna 202 imediatamente; o enriquecimento ocorre em background.

## Endpoint

```http
POST /v1/contacts/{contact_id}/refresh
```

Para números extras: `POST /v1/numbers/{alias}/contacts/{contact_id}/refresh`

**Scope:** `contacts:read`.

## Rate limit

Refresh é mais caro que leitura — usa o WhatsApp Gateway e é throttled por tier:

| Tier | Refresh/min |
| ---- | -----------:|
| free     | 5 |
| solo     | 30 |
| business | 120 |
| custom   | 600 |

Estourar o limite retorna `429 rate_limit_exceeded` com `Retry-After`.

## Exemplo

<Tabs>
<TabItem label="cURL">
```bash
curl -X POST "https://api.turbonotify.com/v1/contacts/ct_.../refresh" \
  -H "Authorization: Bearer $TURBO_API_KEY"
```
</TabItem>
<TabItem label="Node">
```ts
const res = await fetch(`https://api.turbonotify.com/v1/contacts/${id}/refresh`, {
  method: "POST",
  headers: { Authorization: `Bearer ${process.env.TURBO_API_KEY}` },
});
const { accepted_at } = await res.json();
```
</TabItem>
<TabItem label="Python">
```python
r = httpx.post(

)
```
</TabItem>
</Tabs>

## Resposta (202)

<ApiResponse status={202}>
```json
{
  "accepted_at": "2026-05-15T12:00:00Z"
}
```
</ApiResponse>

Quando o enriquecimento concluir, os webhooks `contact.name_changed` ou `contact.picture_changed` podem ser emitidos (se houver mudança).
