Com o **armazenamento próprio** (BYO Storage, de "Bring Your Own"), o Turbo Notify guarda as mídias recebidas e as fotos de perfil de contatos diretamente no seu bucket, sob o seu controle. Sem essa configuração, as mídias recebidas não ficam disponíveis para download.

## Como funciona o armazenamento próprio

Quando um contato envia uma imagem, vídeo, áudio, documento ou figurinha para o seu número de WhatsApp, o Turbo Notify:

1. Recebe a mídia do WhatsApp.
2. Envia o arquivo para o seu bucket (pela API S3).
3. Devolve uma URL pré-assinada diretamente no objeto de mídia (`image.url`, `video.url`, …) quando você consulta `GET /v1/numbers/{alias}/messages/{id}`.
4. Envia o webhook `message.received` com os campos de mídia disponíveis.

Sem armazenamento próprio configurado, o campo `kind` retorna `"unavailable"` com `reason: "no_storage"`. O conteúdo da mídia não é guardado.

## Provedores suportados

O Turbo Notify usa a API HTTP do S3, o mesmo protocolo suportado pelos três provedores:

| Provedor | Plano gratuito | Notas |
|----------|:---------:|-------|
| **Cloudflare R2** | Sim | Sem custo de tráfego de saída; boa escolha quando as mídias são baixadas com frequência. Consulte o site do provedor para os limites atuais. |
| **Supabase Storage** | Sim | Ideal se você já usa Supabase no seu projeto. Consulte o site do provedor para os limites atuais. |
| **AWS S3** | Sim | Maior ecossistema de ferramentas; há custo de tráfego de saída. Consulte o site da AWS para detalhes. |

:::note[Preços]
Não citamos valores porque os planos dos provedores mudam. Confira no site de cada provedor os limites e preços atuais antes de escolher.
:::

## Como configurar

### 1. Crie um bucket no provedor escolhido

O bucket deve ser **privado** (sem acesso público). O Turbo Notify acessa o conteúdo com as credenciais que você informar, não por URLs públicas.

### 2. Crie credenciais com permissões mínimas

As permissões necessárias são:

```
s3:PutObject
s3:GetObject
s3:DeleteObject
s3:ListBucket
```

Crie um usuário IAM (AWS), um token de API do R2 (Cloudflare) ou chaves de acesso S3 nas configurações de Storage do projeto (Supabase), com acesso restrito ao bucket do Turbo Notify.

### 3. Configure no dashboard

Acesse <DashboardLink path="/storage">Armazenamento</DashboardLink> e preencha:

| Campo | Valor |
|-------|-------|
| **Provedor** | AWS S3, Cloudflare R2 ou Supabase Storage |
| **Bucket** | Nome do bucket criado |
| **Região** | Região do bucket (por exemplo `us-east-1`, ou `auto` para R2) |
| **Access Key ID** | Chave de acesso IAM / R2 / Supabase |
| **Secret Access Key** | Chave secreta correspondente |
| **Cloudflare Account ID** / **Supabase Project Ref** | Apenas para R2 e Supabase, respectivamente: o endereço compatível com S3 é montado automaticamente a partir desse valor |

### 4. Valide a conexão e salve

Antes de salvar, clique em **Testar conexão**. O Turbo Notify verifica o bucket (`HEAD`), grava um objeto temporário (`PUT`), lê esse objeto de volta (`GET`) e o remove (`DELETE`), validando as 4 permissões necessárias (`ListBucket`/`PutObject`/`GetObject`/`DeleteObject`). Cada verificação aparece numa lista com o seu resultado, e o botão de salvar só é liberado quando as quatro passam. Depois de salvo, as mídias passam a ser armazenadas imediatamente. Se alguma verificação falhar, confira as credenciais, o nome do bucket e as permissões.

## Comportamento após a configuração

### Mídias recebidas

Toda mídia recebida após a ativação é copiada automaticamente para o seu bucket. Os campos de mídia em `GET /v1/numbers/{alias}/messages/{id}` passam a retornar `kind: "available"`, por exemplo:

```json
{
  "kind": "available",
  "url": "https://<bucket>.r2.cloudflarestorage.com/...?X-Amz-...",
  "expires_at": "2026-04-21T11:00:00Z",
  "mime_type": "image/jpeg",
  "size_bytes": 184320
}
```

O acesso à mídia expira no `expires_at`. Para obter uma nova URL, consulte a mensagem novamente.

### Fotos de perfil de contatos

Com o armazenamento próprio ativo, as fotos de perfil são guardadas no bucket e `GET /v1/numbers/{alias}/contacts/{id}/profile-picture` responde com um redirecionamento 302 para a URL pré-assinada.

### Mídias anteriores à configuração

Mídias recebidas **antes** da ativação do armazenamento próprio continuam com `kind: "unavailable"`. Elas não são recuperadas depois: apenas as novas mídias são armazenadas.

## Solução de problemas

### `kind: "unavailable"` com `reason: "upload_failed"`

O envio para o bucket falhou depois de novas tentativas. Possíveis causas:

- Credenciais expiradas ou com permissões insuficientes.
- Bucket apagado ou com política de acesso alterada.
- Cota do bucket atingida (verifique no console do provedor).

Acesse <DashboardLink path="/storage">Armazenamento</DashboardLink> e clique em **Testar conexão** para diagnosticar.

### `kind: "unavailable"` com `reason: "storage_circuit_open"`

O seu armazenamento falhou várias vezes seguidas e o envio de mídia para ele foi suspenso temporariamente. O Turbo Notify volta a tentar automaticamente. Quando a conexão for restabelecida, você recebe o webhook `storage.recovered`.

### `kind: "pending"`

A mídia ainda está sendo enviada para o bucket. Aguarde alguns segundos e consulte `GET /v1/numbers/{alias}/messages/{id}` novamente. Esse estado só aparece enquanto o envio está em andamento: o webhook `message.received` só é emitido depois que a mídia fica disponível ou indisponível.

## Segurança

- As credenciais são guardadas criptografadas (AES-256-GCM), nunca em texto claro.
- O Turbo Notify nunca expõe credenciais em logs ou respostas.
- URLs pré-assinadas têm validade configurável (padrão: 15 minutos; até 1 hora).
- Recomendamos o **privilégio mínimo**: credenciais com acesso restrito ao bucket do Turbo Notify.
