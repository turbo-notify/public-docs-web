Acompanhe o status de cada número extra cadastrado na sua conta para garantir que esteja ativo e pronto para envio.

## Consultar status

Para verificar o status de um número extra específico, faça uma requisição GET informando o alias do número.

:::note[Status do número principal]
O número principal tem sua própria rota de status, `GET /v1/numbers/main`
(mesmo escopo, `numbers:read`), com uma resposta mais enxuta: sem os
campos `description`, `scheduled_deletion_at`, `reason` e `pairing` (o
pareamento do número principal é feito exclusivamente pelo dashboard, não
tem contrapartida na API pública):

```json
{
  "contact_id": "ct_c7abb1f5ee9640bf86a0a20290810ae9",
  "name": "Laboratório Central",
  "type": "main",
  "alias": "main",
  "number": "5511973117056",
  "status": "connected",
  "at": "2026-04-07T10:00:00Z"
}
```
:::

:::note[`description` e `scheduled_deletion_at` sempre `null` aqui]
Diferente de [Listagem](/numbers/list/), que retorna a `description` real
cadastrada, este endpoint (`GET /v1/numbers/{alias}`) hoje retorna
`description` e `scheduled_deletion_at` sempre como `null`, independente do
valor real. Quando o número está com `status: "pending_deletion"`, o
timestamp da exclusão agendada aparece no campo `at` (não em
`scheduled_deletion_at`). Para a descrição cadastrada, consulte
[Listagem](/numbers/list/).
:::

:::note[`at` acompanha o status atual]
`at` é o momento em que o número **entrou no status atual**: atualiza a
cada transição (pareamento, conexão, queda de conexão, reconexão, falha,
revogação). Um número `disconnected`, `failed`, `reconnecting` etc. reporta
o instante dessa própria transição, então `desconectado desde {at}` /
`falhou em {at}` exibem o horário certo diretamente.

Um número recém-cadastrado (`status: "pending"`) traz em `at` o momento do
cadastro.

A única exceção é `status: "pending_deletion"`, em que `at` traz o momento
da exclusão agendada (veja a nota acima).
:::

## Campos da resposta

| Campo | Tipo | Descrição |
| ----- | ---- | --------- |
| `contact_id` | string\|null | Identificador público (`ct_…`) do contato próprio do número; `null` enquanto não resolvido |
| `name` | string\|null | Nome da conta WhatsApp do número (capturado na conexão); `null` enquanto não houver conexão estabelecida |
| `type` | string | Sempre `"extra"` neste endpoint (números extras), para o principal use `GET /v1/numbers/main` |
| `alias` | string | Identificador único do número extra na conta |
| `number` | string | Número de telefone em dígitos E.164 (sem `+`) |
| `status` | string | Estado atual, veja [Tabela de status](#tabela-de-status) |
| `at` | string | Timestamp ISO 8601 do momento em que o número **entrou no status atual** (`status`): atualiza a cada transição. Exceção: quando `status = "pending_deletion"`, é o momento da exclusão agendada. |
| `description` | string\|null | Sempre `null` neste endpoint hoje, veja nota acima |
| `scheduled_deletion_at` | string\|null | Sempre `null` neste endpoint hoje, veja nota acima |
| `reason` | string\|null | Motivo da falha quando `status` é `"failed"`, veja [Motivos de falha](#motivos-de-falha); `null` em qualquer outro status |
| `pairing` | object\|null | Informações de pareamento: presente apenas durante o processo de vinculação |

### Bloco de pareamento (`pairing`)

Presente quando `status` é `pairing` e o código está pronto (veja
[Pareamento de números extras](/numbers/pairing/#mostrar-o-código)):

| Campo | Tipo | Descrição |
| ----- | ---- | --------- |
| `method` | string | Método de pareamento: `"pairing_code"` |
| `data` | string | Código alfanumérico de 8 caracteres a ser inserido no WhatsApp (exibido com hífen, ex.: `Z5X7-LTYL`) |
| `expires_at` | string | Timestamp ISO 8601 de expiração do código |

## Tabela de status

| Status              | Descrição                                                                 |
| -------------------- | -------------------------------------------------------------------------- |
| `pending`            | Número cadastrado; aguardando início do pareamento.                       |
| `pairing`            | Pareamento em andamento: o código está sendo gerado ou aguardando ser digitado no WhatsApp. |
| `inactive`           | Autenticação obtida, mas a conexão ainda não foi estabelecida.            |
| `connecting`         | Conexão sendo estabelecida (`POST .../connect` aceito).                   |
| `connected`          | O número está vinculado e pronto para envio de mensagens.                 |
| `disconnected`       | Conexão perdida ou desativada; a autenticação é preservada para reconectar. |
| `reconnecting`       | Reconexão automática em andamento após uma queda.                         |
| `failed`             | A vinculação falhou. O motivo vem em `reason`, veja abaixo.               |
| `revoked`            | O dispositivo foi desvinculado pelo WhatsApp.                             |
| `pending_deletion`   | Exclusão agendada (`DELETE /v1/numbers/{alias}`): sobrepõe qualquer outro status até a exclusão. |

## Motivos de falha

Quando `status` é `"failed"`, o campo `reason` diz o que aconteceu, para você
mostrar a mensagem certa ao seu cliente. O mesmo valor chega no evento
[`number.connect.failed`](/messages/webhook/). Em qualquer outro status,
`reason` é `null`.

| Motivo                   | O que aconteceu e o que fazer |
| ------------------------ | ----------------------------- |
| `pairing_timeout`        | O código foi gerado, mas não foi usado a tempo. Peça um novo código. |
| `paired_phone_mismatch`  | Outro WhatsApp concluiu o pareamento. Pareie de novo usando o celular do número cadastrado. |
| `phone_already_bound`    | Este número já está em uso na conta. |
| `main_number_not_connected` | O número principal da conta precisa estar conectado para parear números extras. Reconecte o número principal e pareie de novo. |
| `code_generation_failed` | O WhatsApp não gerou o código naquele momento. Tente de novo em instantes. |
| `connection_lost`        | O número perdeu a conexão com o WhatsApp e precisa ser pareado de novo. |
| `pairing_failed`         | Qualquer outra falha. Pareie de novo. |

Novos motivos podem ser adicionados. Trate um valor que você não conhece como
`pairing_failed`. Para montar a tela de pareamento do seu cliente, veja
[Pareamento de números extras](/numbers/pairing/#experiência-de-pareamento-recomendada).

## Erros possíveis

| Status | Código de erro          | Descrição                                           |
| :----: | ----------------------- | --------------------------------------------------- |
| `402`  | `feature_not_available` | O plano atual não suporta números extras.           |
| `403`  | `not_authorized`        | A chave de acesso está inválida ou ausente.         |
| `403`  | `insufficient_scope`    | A chave de acesso não possui o escopo `numbers:read` (resposta inclui `required_scope`). |
| `404`  | `extra_number_not_found` | O alias informado não foi encontrado na conta.     |
| `500`  | `internal_error`        | Erro interno inesperado no servidor.                |
