Números extras permitem que você envie mensagens a partir de múltiplos números de WhatsApp, além do número principal da sua conta. Cada número extra é vinculado ao WhatsApp por um processo de pareamento: por QR code ou código de vinculação, conforme o método escolhido.

O cadastro dispara uma cobrança pro-rata imediata, cobrindo os dias restantes do ciclo atual, veja [Cobrança de números extras](/numbers/billing/) para o valor, a fórmula e a política de reembolso. O número só é criado se a cobrança for aprovada.

## Cadastro pelo dashboard

A forma mais simples de adicionar um número extra é pelo dashboard do Turbo Notify. Acesse a página de <DashboardLink path="/numbers">Números</DashboardLink> e clique em **Adicionar número**.

Informe o número de telefone com código do país e um alias: o cadastro é confirmado imediatamente, sem código de pareamento nesse momento. Em seguida, abra o número recém-criado, escolha o método de pareamento (QR code ou código de vinculação) e clique em **Vincular número** para gerar o código ou QR correspondente.

**Escopo obrigatório:** `numbers:write`

O cadastro (`POST /v1/numbers`) e o pareamento (obtenção do código a ser
inserido no WhatsApp) são **operações separadas**. `alias` é obrigatório:
deve começar com uma letra, e `description` é opcional. A resposta do
cadastro confirma apenas a criação do número: o `status` sempre nasce
`"pending"` e não há código de pareamento inline:

<ApiResponse
  status={201}
  body={{
    alias: 'vendas_sp',
    phone_number: '5511988888888',
    status: 'pending',
    created_at: '2025-07-16T10:00:00Z',
    description: 'Equipe de vendas SP',
  }}
/>

:::note[O `+` vale para a requisição, não para a resposta]
Repare no `phone_number` acima: a requisição foi enviada com
`"+5511988888888"`, mas a resposta traz `"5511988888888"`, **sem o `+`**.

O `+` é removido na gravação do número. Portanto:

- **Requisição**: `phone_number` **aceita** o `+` inicial (`"+5511988888888"`).
- **Resposta**: `phone_number` **nunca** traz o `+`; são sempre dígitos E.164
  puros (`"5511988888888"`), o mesmo formato do campo `number` em
  [Listagem](/numbers/list/) e [Status](/numbers/status/).

Se você compara o valor enviado com o valor devolvido (para deduplicar ou
confirmar cadastro), normalize removendo o `+` antes de comparar.
:::

## Obtendo o código de pareamento

Depois de criar o número, chame `POST /v1/numbers/{alias}/pair` para
disparar a geração do código:

<ApiResponse
  status={202}
  body={{
    alias: 'vendas_sp',
    status: 'pairing',
  }}
/>

Por essa rota, números extras pareiam por **código de vinculação**
(`pairing_code`): é o único método que a API pública gera hoje para
números extras. O código em si é entregue de forma assíncrona: consulte
[Status dos números extras](/numbers/status/), cujo bloco `pairing` traz
`{method, data, expires_at}` enquanto `status` é `"pairing"`.

### Código digitado errado

Se o código for digitado errado no celular, o WhatsApp invalida esse código
na hora: nem o código correto é aceito depois disso. O WhatsApp não informa
esse erro, então ofereça na sua tela uma opção para gerar um novo código.

Para gerar um novo código, chame `POST /v1/numbers/{alias}/pair` de novo
enquanto o número estiver com `status: "pairing"`. A tentativa anterior é
descartada e o bloco `pairing` do status volta a vir vazio até o novo código
ficar pronto. Mostre sempre o código mais recente.

### O WhatsApp do número cadastrado

O pareamento precisa ser concluído no WhatsApp do número cadastrado. Se outro
WhatsApp digitar o código ou escanear o QR code, o pareamento é recusado, o
dispositivo é desconectado desse WhatsApp e o número fica com `status: "failed"`.
O motivo chega como `reason: "paired_phone_mismatch"`, tanto no
[status](/numbers/status/) quanto no evento
[`number.connect.failed`](/messages/webhook/). Para tentar de novo, chame
`POST /v1/numbers/{alias}/pair` e conclua o pareamento no celular do número
cadastrado.

Depois de pareado, o número aparece em **Dispositivos conectados** no celular com
o nome da sua organização.

## Experiência de pareamento recomendada

Se você oferece números de WhatsApp aos seus próprios clientes, quem pareia o
celular é o seu cliente, na sua tela. Com o fluxo abaixo ele consegue se
resolver sozinho, inclusive quando digita o código errado:

1. **Peça o código.** Chame `POST /v1/numbers/{alias}/pair`.
2. **Mostre o código assim que ele ficar pronto.** Consulte
   `GET /v1/numbers/{alias}` a cada 2 segundos enquanto `status` for
   `"pairing"`. Quando o bloco `pairing` vier preenchido, exiba `pairing.data`
   e uma contagem regressiva até `pairing.expires_at`. Se `pairing` voltar
   `null` depois de um código já exibido, um novo código está sendo gerado:
   mostre "gerando novo código" e continue consultando.
3. **Deixe "Gerar novo código" sempre visível.** O WhatsApp não avisa quando
   o código é digitado errado, e depois de um erro nem o código certo é mais
   aceito. Esse botão chama `POST /v1/numbers/{alias}/pair` de novo; use-o
   também quando a contagem chegar a zero.
4. **Encerre pelo resultado.** `status: "connected"` significa que deu certo.
   `status: "failed"` traz o motivo em `reason`; mostre a mensagem da tabela
   abaixo e ofereça tentar de novo. Se você usa webhooks, os eventos
   [`number.connected`](/messages/webhook/) e
   [`number.connect.failed`](/messages/webhook/) (com o mesmo `reason`)
   substituem a consulta para saber o resultado; o código em si só é
   entregue pela consulta de status, por ser uma credencial de curta duração.

| `reason` | O que dizer ao seu cliente |
| -------- | -------------------------- |
| `pairing_timeout` | O código expirou antes de ser usado. Gere um novo código. |
| `paired_phone_mismatch` | O código foi usado em outro WhatsApp. Use o celular do número cadastrado. |
| `phone_already_bound` | Este número já está em uso na conta. |
| `no_active_session` | O número principal da conta precisa estar conectado antes. |
| `code_generation_failed` | O WhatsApp não gerou o código agora. Tente de novo em instantes. |
| `connection_lost` | O número perdeu a conexão com o WhatsApp. Pareie de novo. |
| `pairing_failed` | Não foi possível concluir o pareamento. Tente de novo. |

Trate valores de `reason` que você não conhece como `pairing_failed`: novos
motivos podem ser adicionados.

### Limite de tentativas

Cada chamada de `POST /v1/numbers/{alias}/pair` pede um código novo ao
WhatsApp e gera uma notificação no celular. Pedidos seguidos demais fazem o
próprio WhatsApp bloquear novos códigos para aquele número por um tempo. Para
proteger o número do seu cliente, o pareamento aceita até **10 pedidos por
minuto por número** e **30 por minuto na conta**. Acima disso a resposta é
`429 pairing_rate_limited`, com o cabeçalho `Retry-After` em segundos:

<ApiResponse
  status={429}
  headers={{ 'Retry-After': '42' }}
  body={{
    error: 'pairing_rate_limited',
  }}
/>

Mostre ao seu cliente quanto tempo falta, a partir de `Retry-After`, em vez
de repetir a chamada.

### Erros do pedido de pareamento

| Status | Código de erro | Descrição |
| :----: | -------------- | --------- |
| `402`  | `subscription_inactive` | A assinatura da organização não está ativa. |
| `402`  | `feature_not_available` | O plano atual não inclui números extras. |
| `403`  | `main_number_pair_not_allowed` | O número principal é pareado pelo dashboard, não por esta rota. |
| `404`  | `extra_number_not_found` | O alias informado não existe na conta. |
| `409`  | `already_paired_or_connected` | O número já está pareado ou conectado. |
| `429`  | `pairing_rate_limited` | Limite de tentativas atingido; aguarde `Retry-After` segundos. |

## Usabilidade

- Cada número extra deve pertencer a um aparelho com WhatsApp ativo.
- O código de pareamento tem validade limitada: use `pairing.expires_at` do [status](/numbers/status/) para a contagem regressiva. Caso expire ou seja digitado errado, chame `POST /v1/numbers/{alias}/pair` novamente (veja [Experiência de pareamento recomendada](#experiência-de-pareamento-recomendada)).
- `alias` é obrigatório no cadastro e deve começar com uma letra: use-o no envio de mensagens via URL (`/v1/numbers/{alias}/...`).
- O número nasce com status `pending` e só avança para `pairing` após a chamada de pareamento.

## Status

Após cadastrar o número extra, acompanhe o andamento da vinculação consultando o [Status dos números extras](/numbers/status/).

## Erros possíveis

Veja os principais erros que podem ocorrer no cadastro de números extras:

| Status | Código de erro           | Descrição                                              |
| :----: | ------------------------ | ------------------------------------------------------ |
| `400`  | `invalid_json`           | O `alias` está vazio ou é inválido. (Um corpo de requisição malformado retorna `422 validation_error`, não este código.) |
| `400`  | `reserved_alias`         | O alias `"main"` é reservado para o número principal e não pode ser usado em um número extra. |
| `400`  | `no_payment_method`      | A organização não tem forma de pagamento cadastrada. Nenhuma cobrança é tentada e nenhum número é criado. |
| `402`  | `subscription_inactive`  | A assinatura da organização está `past_due`, `terminated`, `pending` ou com trial expirado (resposta inclui `details.status`). |
| `402`  | `feature_not_available`  | O plano atual não suporta números extras.              |
| `402`  | `extra_numbers_limit_reached` | A organização já atingiu o teto de números extras do tier (BUSINESS 1.000 / CUSTOM 1.000). A resposta inclui `details.limit` e `details.current`. |
| `402`  | `payment_declined`       | A cobrança pro-rata de ativação (veja [Cobrança de números extras](/numbers/billing/)) foi recusada pela forma de pagamento. Nenhum número é criado. |
| `402`  | `payment_requires_authentication` | A forma de pagamento exige reautenticação (3DS) e não pode ser cobrada automaticamente. Nenhum número é criado. |
| `403`  | `not_authorized`         | A chave de acesso está inválida ou ausente.            |
| `403`  | `insufficient_scope`     | A chave de acesso não possui o escopo `numbers:write` (resposta inclui `required_scope`). |
| `409`  | `number_already_exists`  | O alias ou o número informado já está cadastrado na conta. |
| `500`  | `internal_error`         | Erro interno inesperado no servidor.                   |
| `503`  | `payment_gateway_unavailable` | A cobrança de ativação não pôde ser confirmada a tempo. Nenhum número é criado; tente novamente. |
