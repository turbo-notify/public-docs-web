Números extras permitem que você envie mensagens a partir de múltiplos números de WhatsApp, além do número principal da sua conta. Cada número extra é vinculado ao WhatsApp por um processo de pareamento: por QR code ou código de vinculação, conforme o método escolhido.

O cadastro dispara uma cobrança pro-rata imediata, cobrindo os dias restantes do ciclo atual, veja [Cobrança de números extras](/numbers/billing/) para o valor, a fórmula e a política de reembolso. O número só é criado se a cobrança for aprovada.

## Cadastro pelo dashboard

A forma mais simples de adicionar um número extra é pelo dashboard do Turbo Notify. Acesse a página de <DashboardLink path="/numbers">Números</DashboardLink> e clique em **Adicionar número**.

Informe o número de telefone com código do país e um alias: o cadastro é confirmado imediatamente, sem código de pareamento nesse momento. Em seguida, abra o número recém-criado, escolha o método de pareamento (QR code ou código de vinculação) e clique em **Vincular número** para gerar o código ou QR correspondente.

**Escopo obrigatório:** `numbers:write`

O cadastro (`POST /v1/numbers`) e o pareamento (obtenção do código a ser
inserido no WhatsApp) são **operações separadas**. `alias` é obrigatório:
deve começar com uma letra, e `description` é opcional. A resposta do
cadastro confirma apenas a criação do número: o `status` sempre nasce
`"pending"` e não há código de pareamento inline:

<ApiResponse
  status={201}
  body={{
    alias: 'vendas_sp',
    phone_number: '5511988888888',
    status: 'pending',
    created_at: '2025-07-16T10:00:00Z',
    description: 'Equipe de vendas SP',
  }}
/>

:::note[O `+` vale para a requisição, não para a resposta]
Repare no `phone_number` acima: a requisição foi enviada com
`"+5511988888888"`, mas a resposta traz `"5511988888888"`, **sem o `+`**.

O `+` é removido na gravação do número. Portanto:

- **Requisição**: `phone_number` **aceita** o `+` inicial (`"+5511988888888"`).
- **Resposta**: `phone_number` **nunca** traz o `+`; são sempre dígitos E.164
  puros (`"5511988888888"`), o mesmo formato do campo `number` em
  [Listagem](/numbers/list/) e [Status](/numbers/status/).

Se você compara o valor enviado com o valor devolvido (para deduplicar ou
confirmar cadastro), normalize removendo o `+` antes de comparar.
:::

## Obtendo o código de pareamento

Depois de criar o número, chame `POST /v1/numbers/{alias}/pair` para
disparar a geração do código:

<ApiResponse
  status={202}
  body={{
    alias: 'vendas_sp',
    status: 'pairing',
  }}
/>

Por essa rota, números extras pareiam por **código de vinculação**
(`pairing_code`): é o único método que a API pública gera hoje para
números extras. O código em si é entregue de forma assíncrona: consulte
[Status dos números extras](/numbers/status/), cujo bloco `pairing` traz
`{method, data, expires_at}` enquanto `status` é `"pairing"`.

## Usabilidade

- Cada número extra deve pertencer a um aparelho com WhatsApp ativo.
- O código de pareamento tem validade limitada (aproximadamente 180 segundos). Caso expire, chame `POST /v1/numbers/{alias}/pair` novamente.
- `alias` é obrigatório no cadastro e deve começar com uma letra: use-o no envio de mensagens via URL (`/v1/numbers/{alias}/...`).
- O número nasce com status `pending` e só avança para `pairing` após a chamada de pareamento.

## Status

Após cadastrar o número extra, acompanhe o andamento da vinculação consultando o [Status dos números extras](/numbers/status/).

## Erros possíveis

Veja os principais erros que podem ocorrer no cadastro de números extras:

| Status | Código de erro           | Descrição                                              |
| :----: | ------------------------ | ------------------------------------------------------ |
| `400`  | `invalid_json`           | O `alias` está vazio ou é inválido. (Um corpo de requisição malformado retorna `422 validation_error`, não este código.) |
| `400`  | `reserved_alias`         | O alias `"main"` é reservado para o número principal e não pode ser usado em um número extra. |
| `400`  | `no_payment_method`      | A organização não tem forma de pagamento cadastrada. Nenhuma cobrança é tentada e nenhum número é criado. |
| `402`  | `subscription_inactive`  | A assinatura da organização está `past_due`, `terminated`, `pending` ou com trial expirado (resposta inclui `details.status`). |
| `402`  | `feature_not_available`  | O plano atual não suporta números extras.              |
| `402`  | `extra_numbers_limit_reached` | A organização já atingiu o teto de números extras do tier (BUSINESS 1.000 / CUSTOM 1.000). A resposta inclui `details.limit` e `details.current`. |
| `402`  | `payment_declined`       | A cobrança pro-rata de ativação (veja [Cobrança de números extras](/numbers/billing/)) foi recusada pela forma de pagamento. Nenhum número é criado. |
| `402`  | `payment_requires_authentication` | A forma de pagamento exige reautenticação (3DS) e não pode ser cobrada automaticamente. Nenhum número é criado. |
| `403`  | `not_authorized`         | A chave de acesso está inválida ou ausente.            |
| `403`  | `insufficient_scope`     | A chave de acesso não possui o escopo `numbers:write` (resposta inclui `required_scope`). |
| `409`  | `number_already_exists`  | O alias ou o número informado já está cadastrado na conta. |
| `500`  | `internal_error`         | Erro interno inesperado no servidor.                   |
| `503`  | `payment_gateway_unavailable` | A cobrança de ativação não pôde ser confirmada a tempo. Nenhum número é criado; tente novamente. |
