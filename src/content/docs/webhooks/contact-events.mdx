Lista de eventos webhook emitidos pelo Turbo Notify para mudanças relacionadas a TN Contacts. Você precisa configurar a URL e habilitar `contact.*` no dashboard.

## Tabela

| Evento | Quando |
| ------ | ------ |
| `contact.created` | Primeira observação do par `(tenant, telefone)` |
| `contact.name_changed` | `push_name` divergiu do snapshot anterior |
| `contact.picture_changed` | WhatsApp emitiu `PictureUpdate` ou refresh detectou hash novo |
| `contact.business_profile_changed` | `BusinessAccountUpdate` no WhatsApp |
| `contact.phone_added` | Rotação de JID associou novo número ao mesmo `contact_id` |
| `contact.first_messaged` | Tenant enviou primeira mensagem outbound para este contato (slot consumido) |
| `contact.quota.warning` | Cruzou threshold 80/90/95% da quota mensal |
| `contact.quota.exceeded` | Tentativa rejeitada por estouro (HTTP 402) |

## PII discipline

Telefones aparecem sempre **mascarados** no payload (`+5571****4756`). O nome do contato (`push_name`) é PII e nunca é logado cru pelo TN — você recebe via webhook e é responsável pelo armazenamento subsequente.


## Exemplo: `contact.quota.warning`

```json
{
  "event_id": "evt_...",
  "event_type": "contact.quota.warning",
  "tenant_id": "tnt_...",
  "occurred_at": "...",
  "data": {
    "threshold_bps": 90,
    "used": 90,
    "quota": 100,
    "resets_at": "2026-06-14T...",
    "tier": "FREE"
  }

```

`threshold_bps` é integer em basis points: `80 | 90 | 95 | 100`.

## Idempotency

Cada evento carrega `event_id` único. Use `event_id` como chave de deduplicação no seu side.

Internamente o publisher TN usa `Nats-Msg-Id` com formato `{tenant_id}:{contact_id}:{event_kind}` para idempotência no broker.
