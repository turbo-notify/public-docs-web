Returns the full payload of a contact, including the phone and the profile picture metadata.

## Endpoint

```http
GET /v1/contacts/{contact_id}
```

For extra numbers: `GET /v1/numbers/{alias}/contacts/{contact_id}`

**Required scope:** `contacts:read`.

## Path parameter

| Parameter | Type | Format |
| --------- | ---- | ------ |
| `contact_id` | string | `ct_{hex32}`: regex `^ct_[0-9a-f]{32}$` |

The `number_alias` (right after `id`) identifies the Turbo Notify number this
contact belongs to: `"main"` or the alias of an extra number (the same
phone reached by two different numbers produces two distinct contacts). The
`phone_number` is the **full E.164** (unmasked), the same number that
appears in `message.from`/`message.to`. The `name` field is the name the
contact set in their WhatsApp profile (the same `{id, name, number}` trio
used by the `contact.*` events). The shape of `picture` depends on `kind`
(`available` or `unavailable`), just like the media block of the
events; when `kind` is `available`, the block itself carries `fetched_at`.
The `pending` value only appears in webhook payloads: this read endpoint
never returns it.

### Interaction and refresh dates

| Field | Meaning |
| ----- | ------- |
| `first_messaged_at` | When the first message sent by this number through Turbo Notify reached the contact on WhatsApp. `null` while none has arrived. A send that failed before reaching WhatsApp does not fill in this field. |
| `last_interaction_at` | The last message actually exchanged with the contact, in either direction: received, sent from the phone, or sent through Turbo Notify and delivered to WhatsApp. A send that did not reach WhatsApp does not change this field. |
| `refresh` | The last [refresh request](/en/contacts/refresh/) you made for this contact. `null` if you never made one. Carries `requested_at`, `completed_at` and `outcome`; the last two stay `null` while the refresh is in progress. |

## Errors

- `404 contact_not_found`: the contact does not exist, or belongs to another organization or to another number. A `contact_id` outside the `ct_{hex32}` format returns `400 invalid_contact_id`.

See the [error reference](/en/contacts/errors/).
