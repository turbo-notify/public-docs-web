## Error table

| HTTP | `error` | When |
| ---- | ------- | ---- |
| 400  | `invalid_contact_id` | `contact_id` does not match `^ct_[0-9a-f]{32}$` |
| 400  | `invalid_cursor` | Opaque cursor is corrupted |
| 402  | `contact_quota_exceeded` | The cycle's distinct-contacts quota was reached |
| 404  | `contact_not_found` | Invalid id, or belongs to another organization |
| 404  | `contact_picture_unavailable` | Rare — presigned-URL generation for the picture failed on this request. The absence of a picture (no storage, upload failed, contact has no picture) does **not** return 404: see [Profile Picture](/en/contacts/profile-picture/) |
| 429  | `refresh_rate_limited` | Refresh-per-minute limit exceeded |

A contact id accessed under the **wrong** `{alias}` also surfaces as
**`contact_not_found`** (404) — ids are globally unique but not
alone-addressable (see [number-nested routes](/en/changelog/2026-06-22-number-scoped-routes/)).
For the primary number the flat routes (`/v1/contacts/{id}` etc.) are also
available as a shorthand; for extra numbers always use the nested form with
the correct `{alias}`.

## 402 response example

Returned when the organization tries to reach, via Turbo Notify, a contact
that becomes counted for the current cycle — a **new** contact or a
**returning** contact not yet counted this cycle — and the cycle's
distinct-contacts quota is already exhausted.

<ApiResponse status={402}>
```json
{
  "error": "contact_quota_exceeded",
  "message": "Distinct-contacts quota exceeded for tier SOLO (100/100 this cycle)",
  "details": {
    "quota": 100,
    "used": 100,
    "resets_at": "2026-08-01T00:00:00Z",
    "tier": "SOLO"
  }
}
```
</ApiResponse>

**Recommended action:** upgrade the plan. Unlike 429, a 402 carries no
`Retry-After` — the error is structural (the evaluated billing cycle needs to
close, at `resets_at`, or the tier needs to go up).

## 402 vs 429 — when each appears

| | 402 Payment Required | 429 Too Many Requests |
| - | --------------------- | ---------------------- |
| Semantics | Structural — "upgrade the plan" | Temporal — "retry later" |
| Header | — | `Retry-After: <seconds>` |
| Reset | At the end of the evaluated billing cycle (`resets_at`), or upgrade | In seconds/minutes |
| When | Cycle quota | Burst protection |

See also: [Usage & Quota](/en/usage/quota/).
