Reactions let your application add or remove a reaction on a specific message, making conversations more expressive.

The endpoint is addressed by the target message's `message_id` in the URL: there is no `to` field in the body, because the recipient is taken from the original message.

This page covers **sending** and removing reactions. To list the active reactions on a message, see [Get reactions](/en/messages/reactions/).

Before sending the reaction, Turbo Notify opens the conversation the way a person would: the number shows as online, the unread messages in the target message's chat are marked as read, and only then is the reaction sent. See [Mark as read](/en/other-features/mark-as-read/).

## Add a reaction

`POST /v1/messages/{message_id}/react`: adds a reaction to the message identified by `{message_id}` (format `msg_{hex32}`). This route acts on the main number. To react from an extra number, use the full form `POST /v1/numbers/{alias}/messages/{message_id}/react` with the number's alias in the URL path.

The outcome arrives by webhook as `message.reacted` (success) or `message.react.failed` (failure). The failure payload includes the target message's `message_id`, so you do not need `request_id` to match it.

## Reacting from an extra number

To react from a registered, active [extra number](/en/numbers/add/), put that number's alias in the URL path. The recipient is still taken from the `message_id`.

```bash title="reaction.sh"
curl -X POST \
  https://api.turbonotify.com/v1/numbers/vendas-sp/messages/msg_01993c5a1b24d3e9f01a2b3c4d5e6f70/react \
  -H "Authorization: Bearer YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "reaction": "🎉"
  }'
```

If the alias in the URL is not registered as an extra number, or the number is not active, the request is rejected.

Learn more about [extra numbers](/en/numbers/add/).

## Possible errors

| Status | Error code              | Description                                        |
| :----: | ----------------------- | -------------------------------------------------- |
| `400`  | `invalid_message_id`    | The `message_id` in the URL is not in the `msg_{hex32}` format. |
| `402`  | `feature_not_available` | The feature is not available on your plan. |
| `403`  | `not_authorized`        | The API key is invalid or missing.                 |
| `403`  | `insufficient_scope`    | The API key does not have the `messages:send` scope (the response includes `required_scope`). |
| `404`  | `number_not_found`      | The `{alias}` in the path does not match any number on the account (on the flat route: the account has no main number yet). |
| `404`  | `not_found`             | The message was not found, belongs to another organization, is outside your plan's [content retention window](/en/messages/retention/), or (on the nested route `/numbers/{alias}/messages/.../react`) belongs to a number other than the alias in the URL: all of these cases return the same response, with no distinction. |
| `404`  | `message_not_found`     | *(only on the shortcut route without `{alias}`, `POST /v1/messages/{id}/react`)* The `message_id` exists but belongs to an extra number, not the main number. |
| `409`  | `number_not_connected` | The sending number is not connected to WhatsApp. Reconnect the number and try again. |
| `422`  | `message_not_reactable` | The target message has not been sent to WhatsApp yet, or has already been deleted. |
| `422`  | `sender_not_found`      | The alias or number given does not match any sender on the account. |
| `422`  | `validation_error`      | The request body is malformed or failed validation. The response includes `details.errors` with the list of invalid fields. |
| `500`  | `internal_error`        | Unexpected internal server error.                  |

The two `404` codes are only distinct on the main number's shortcut route (no `{alias}` in the URL): there, `not_found` means "does not exist, is not yours, or is already past your plan's retention window", while `message_not_found` means "exists, but belongs to an extra number". On the nested route `/numbers/{alias}/messages/...`, both cases (a message that does not exist and a message from another number) return the same `not_found`: if you know the message exists but got `not_found`, check that you are using the alias of the number that sent or received it.
