The `message.quota.warning` and `message.quota.exceeded` events are **per-number**
(ADR 2026-07-02, mirroring `contact.quota.*`): message quota is scoped to a single
number, so these events carry **`number_alias`** in the envelope (immediately below
`organization_id`) identifying the number whose message quota was reached — `main` or an
extra-number alias. The event `data` (quota fields `threshold_bps`, `used`, `quota`,
`window_days`, `resets_at`, `tier`, `channel`, `origin`) is unchanged — `number_alias`
rides the envelope, never `data`.

```json title="message.quota.warning envelope"
{
  "id": "evt_…",
  "type": "message.quota.warning",
  "organization_id": "org_…",
  "number_alias": "main",
  "created_at": "2026-05-15T12:00:00Z",
  "data": { /* threshold_bps, used, quota, window_days, resets_at, tier, channel, origin — unchanged */ }
}
```

`number_alias` is now omitted **only** on `storage.*`; every `*.quota.*` family
(contacts and messages) carries it. Only messages sent **via Turbo Notify**
(`origin: "tn"`) consume the quota. See [Contact events](/webhooks/contact-events/)
for the identical envelope treatment.
