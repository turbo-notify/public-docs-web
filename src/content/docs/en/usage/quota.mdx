| Quota | Route | Scope |
| ----- | ----- | ----- |
| Account usage | `GET /v1/usage` | Account roll-up (top-level) = sum across numbers |
| Message usage (account) | `GET /v1/usage/messages` | Account roll-up (top-level) |
| Message quota (per number) | `GET /v1/numbers/{alias}/messages/quota` | Per-number |
| Contact quota (per number) | `GET /v1/numbers/{alias}/contacts/quota` | Per-number |

Both the **message** quota (ADR 2026-07-02) and the **contact** quota are now
**per-number**: each number (`main` or an extra-number alias) has its own allowance,
so an organization with N numbers gets N× the tier allowance, and exhausting one
number's quota does not block another. Query each under its number; for the main number
you can also use the flat routes `GET /v1/messages/quota` and `GET /v1/contacts/quota`.
Only traffic sent **via Turbo Notify** (`origin: "tn"`) consumes the quota.

Account-wide usage (`GET /v1/usage`, `GET /v1/usage/messages`) stays **top-level** and
is the **account roll-up = the sum of the per-number usages**.

The per-number quota endpoints return
`{ used, quota, remaining, window_days, resets_at, tier }`.
