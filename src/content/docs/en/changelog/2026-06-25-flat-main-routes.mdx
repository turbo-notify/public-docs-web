---
title: Flat routes for the primary number
description: The routes /v1/messages, /v1/contacts and /v1/groups now point directly to the primary number, without needing to specify the alias.
sidebar:
  order: 7
---

From this version on, all primary-number operations can be performed
directly without specifying the alias in the URL:

| New flat route | Equivalent |
|---|---|
| `POST /v1/messages` | `POST /v1/numbers/main/messages` |
| `GET  /v1/messages` | `GET  /v1/numbers/main/messages` |
| `GET  /v1/messages/{id}` | `GET  /v1/numbers/main/messages/{id}` |
| `GET  /v1/contacts` | `GET  /v1/numbers/main/contacts` |
| `GET  /v1/contacts/quota` | `GET  /v1/numbers/main/contacts/quota` |
| `GET  /v1/groups` | `GET  /v1/numbers/main/groups` |
| `POST /v1/typing-indicator` | `POST /v1/numbers/main/typing-indicator` |
| *(and all sub-routes)* | |

The `/v1/numbers/main/…` form continues to work normally and produces
identical responses. For **extra numbers**, continue using `/v1/numbers/{alias}/…`.

This change requires no modifications to existing integrations.
