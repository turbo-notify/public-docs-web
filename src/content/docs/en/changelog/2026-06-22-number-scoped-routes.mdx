**Date:** 2026-06-22
**Status:** Applied

:::caution[Route change — breaking]
This is a **breaking route change**. Every call to messages, contacts and groups
must migrate to the number-nested path (`/v1/numbers/{alias}/…`). The old flat
routes (`/v1/messages`, `/v1/contacts`, `/v1/groups` and their sub-routes) now
return **404**.
:::

## What changed

### Messages, contacts and groups always below the number

Messages, contacts and groups are now **always associated with a number** of your
organization. The API expresses this **structurally**: the routes live below the
number route, identified by `{alias}` (`main` for the primary number or the alias
of an extra number).

| Before (flat — now 404) | Now (number-nested) |
| ----------------------- | ------------------- |
| `POST /v1/messages` | `POST /v1/numbers/{alias}/messages` |
| — (no public list existed) | `GET /v1/numbers/{alias}/messages` (cursor list — **new**) |
| `GET /v1/messages/{id}` | `GET /v1/numbers/{alias}/messages/{id}` |
| `GET /v1/messages/{id}/status` | `GET /v1/numbers/{alias}/messages/{id}/status` |
| `GET /v1/messages/{id}/reactions` | `GET /v1/numbers/{alias}/messages/{id}/reactions` |
| `GET /v1/messages/{id}/receipts` | `GET /v1/numbers/{alias}/messages/{id}/receipts` |
| `POST /v1/messages/{id}/reply` | `POST /v1/numbers/{alias}/messages/{id}/reply` |
| `POST /v1/messages/{id}/edit` | `POST /v1/numbers/{alias}/messages/{id}/edit` |
| `POST /v1/messages/{id}/delete` | `POST /v1/numbers/{alias}/messages/{id}/delete` |
| `POST /v1/messages/{id}/react` | `POST /v1/numbers/{alias}/messages/{id}/react` |
| `POST /v1/typing-indicator` | `POST /v1/numbers/{alias}/typing-indicator` |
| `GET /v1/contacts` | `GET /v1/numbers/{alias}/contacts` |
| `GET /v1/contacts/{id}` | `GET /v1/numbers/{alias}/contacts/{id}` |
| `GET /v1/contacts/{id}/profile-picture` | `GET /v1/numbers/{alias}/contacts/{id}/profile-picture` |
| `GET /v1/contacts/quota` | `GET /v1/numbers/{alias}/contacts/quota` |
| `POST /v1/contacts/{id}/refresh` | `POST /v1/numbers/{alias}/contacts/{id}/refresh` |
| `GET /v1/groups` | `GET /v1/numbers/{alias}/groups` |
| `GET /v1/groups/{id}` | `GET /v1/numbers/{alias}/groups/{id}` |
| `GET /v1/groups/{id}/picture` | `GET /v1/numbers/{alias}/groups/{id}/picture` |

### Send no longer accepts a body `from`

Because the sender is now the path number, the body `from` field has been
**removed**. To send from the primary number use `POST /v1/numbers/main/messages`;
for an extra number use its alias (`POST /v1/numbers/{alias}/messages`). The `to`
field (recipient) is unchanged and still accepts `number`, `group_id` or
`contact_id`.

### Unique IDs, but no longer alone-addressable

Public ids (`msg_…`, `ct_…`, `grp_…`) stay globally unique but are **no longer
alone-addressable**: to read or act on a resource by id you need the
`number_alias` it belongs to. That handle is **always present in the envelope** of
every webhook, `GET /v1/events` item and send response — read it from there and
use it on subsequent by-id calls. Accessing an id under the wrong alias returns
**404**.

### Idempotency key per alias

The idempotency-key scope (`Idempotency-Key`) becomes
`(organization, number_alias, key)`. The same key on two different aliases
produces **two independent sends**.

### `contact.quota.*` is now per-number

The `contact.quota.warning` and `contact.quota.exceeded` events now carry the
**`number_alias` field in the envelope** (immediately below `organization_id`),
identifying the number whose contact quota was reached. The event `data` is
unchanged. `number_alias` stays **omitted** only on `storage.*` and the
message-quota events (`message.quota.*`).

### `GET /v1/events` accepts the `number_alias` filter

The polling route `GET /v1/events` gains an optional **`number_alias`** parameter
that restricts the response to the events of a single number. Account-wide
surfaces (`GET /v1/usage`, `GET /v1/usage/messages`, `GET /v1/events`,
`storage.*`) stay **top-level** and were not affected by the route change.

## Compatibility

Pre-production: the change is breaking with no transition layer. Flat routes
return 404 immediately. Migrate every call to the nested path and start reading
`number_alias` from the envelope for by-id calls.
