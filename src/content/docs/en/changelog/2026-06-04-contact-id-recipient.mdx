## What's New

### `to.contact_id` as recipient

The send endpoint (`POST /v1/numbers/{alias}/messages`) now accepts `{"contact_id": "ct_…"}` as a third mutually exclusive form for the `to` field, alongside `{"number": "…"}` and `{"group_id": "…"}`.

> Note: at the time of this change the route was the flat `POST /v1/messages`. It was later moved under the number ([2026-06-22](/changelog/2026-06-22-number-scoped-routes/)).

The phone number is resolved automatically from the TN Contacts catalog.

**New error codes:**
- `contact_not_found` (HTTP 422) — the supplied `contact_id` does not belong to this organization.
- `contacts_not_enabled` (HTTP 422) — feature not configured on this deployment.

## Doc Fix

Code examples incorrectly showed `"to": "+5511999999999"` (bare string). The correct format has always been `"to": {"number": "+5511999999999"}`.

## Breaking Change

The `to` field validation error messages have changed to reflect the third option. Clients parsing the raw error string should update.
