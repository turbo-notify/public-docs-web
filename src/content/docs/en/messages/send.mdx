```http title="Send a message"
POST /v1/numbers/{alias}/messages
```

The **sender is the path number** — `{alias}` is `main` (primary number) or an
extra-number alias. The request body no longer has a `from` field.

- **`to`** — recipient, exactly one of `number`, `group_id` or `contact_id`.
- **`content`** — nested object describing the message (text, media, etc.).

```bash
curl -X POST https://api.turbonotify.com/v1/messages \
  -H "Authorization: Bearer tn_live_..." \
  -H "Content-Type: application/json" \
  -d '{
    "to": { "number": "+5511999999999" },
    "content": { "text": "Hello from Turbo Notify" }
  }'
```

To reply to a message, use `POST /v1/messages/{id}/reply`. The
`Idempotency-Key` scope is `(organization, number_alias, key)`. For extra
numbers use `POST /v1/numbers/{alias}/messages`.

## Mentions (@mentions)

Since 2026-07-03, write **`@<number>`** tokens directly in `content.text` (or in
a media `caption` — image/video/document; audio/sticker have no caption) to
produce a **real WhatsApp mention** (tappable name + notification on the
mentioned person's device): `@` followed by the contact's phone as E.164 digits
**without `+`**.

```bash
curl -X POST https://api.turbonotify.com/v1/messages \
  -H "Authorization: Bearer tn_live_..." \
  -H "Content-Type: application/json" \
  -d '{
    "to": { "group_id": "grp_e442553a56b14e2695f6acfd7d651b1a" },
    "content": { "text": "Good morning @5511987650000, your order has arrived!" }
  }'
```

Detection is **implicit** — there is no `mentions` request field. Invalid or
non-canonicalizable digit runs (emails, `@+55…`, more than 15 digits) stay plain
text — the send never fails because of a mention (fail-open). Brazilian
12-digit tokens are normalized to the canonical 13-digit form in the
stored/public content. Works in 1:1 chats and groups, and never consumes
message or contact quota. The resulting message carries a hydrated `mentions`
array (`{contact_id?, name?, number}` items) on `GET …/messages/{id}` and on
the `message.sent`/`replied`/`edited` event `data`; a received `@<number>`
token can be pasted straight back into a send (echo symmetry).

## Sending to a group

Since 2026-05-25, sending to a `group_id` requires a **BUSINESS** (or
higher) plan — the `groups:messages` feature. On `FREE`/`SOLO` the send is
rejected:

```json title="402 Payment Required"
{
  "error": "feature_not_available"
}
```

See [Quota and usage](/en/usage/quota/#sending-to-groups-requires-business-or-above)
and the canonical [PT-BR page](/messages/send/#envio-para-grupo) for full details.
