Send messages with Turbo Notify simply, securely and in line with the <ExternalLink href="https://www.whatsapp.com/legal/business-policy/">WhatsApp policies</ExternalLink>.

The body of `POST /v1/numbers/{alias}/messages` (or the
`POST /v1/messages` shortcut for the main number) carries the message
content in the **`content`** object. The type is recognized automatically
from the anchor field present in `content` (`text`, `image_url`,
`latitude`, `start_at`, …). **Do not send** a `content_type` field in the
request: it is never accepted (including it returns `422`).
Text, location, contact, calendar, message with a link button
(`interactive_type`) and media (`image`, `video`, `audio`, `document`, `sticker`, see
[Sending media](/en/messages/send-media/)) are supported.

To quote (reply to) an existing message (any content variant), use the dedicated `POST /v1/messages/{message_id}/reply` endpoint, where `{message_id}` is the public id of the quoted message (`msg_{hex32}`). The body of that request contains only `content`. The resulting webhook is `message.replied` (instead of `message.sent`); see [Webhooks](/en/messages/webhook/#example-messagereplied-inboundoutbound).

The quoted message must be **within your plan's [content retention window](/en/messages/retention/)**: replying to a message older than the window returns `404 not_found`, the same response as for a message that does not exist.

Before sending (or replying), Turbo Notify opens the chat the way a person would: the number shows as online, the unread messages in the destination chat are marked as read, and only then is the message sent. To mark a chat as read without sending anything, see [Mark as read](/en/other-features/mark-as-read/).

:::tip[Routing by number]
- **Main number** → `POST /v1/messages` (short route) **or** `POST /v1/numbers/main/messages`: both forms are identical.
- **Extra number** → `POST /v1/numbers/{alias}/messages`, where `{alias}` is the alias set in the dashboard. [Learn more](/en/numbers/add/).
:::

## Basic send

The simplest send needs only the recipient's number and the message text. Turbo Notify automatically uses your account's main number as the sender.

      -H "Authorization: Bearer YOUR_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "to": {"number": "+5511988887777"},
        "content": {
          "text": "Hello, this message was sent with Turbo Notify!"

## Mentions (@mentions)

To mention
someone (a real WhatsApp mention, with a tappable name and a notification on
the mentioned person's phone), write the **`@<number>`** token directly in the
`text` (or in a media `caption`, see [Sending media](/en/messages/send-media/)):
`@` followed by the contact's phone number as **E.164 digits, without `+`**.

```json title="POST /v1/messages: text with a mention (1:1)"
{
  "to": { "number": "+5511988887777" },
  "content": {
    "text": "Hi @5511977776666, your order has arrived!"
  }
}
```

In groups, mention a participant by number:

```json title="POST /v1/messages: group mentioning a participant"
{
  "to": { "group_id": "grp_e442553a56b14e2695f6acfd7d651b1a" },
  "content": {
    "text": "Good morning @5511977776666, can you check today's order?"
  }
}
```

**There is no `mentions` field in the request**: detection is **implicit**,
from the text itself (the same model used to infer the content type from the
anchor field). Every valid token becomes a real mention on the recipient's
device.

### Token rules

| Rule | Behavior |
|---|---|
| Syntax | `@` + 7 to 15 digits, delimited by a word boundary: `name@domain.com`, `@@123`, sequences longer than 15 digits and `@+55…` do **not** become mentions |
| Normalization | 12-digit Brazilian numbers are normalized to the 13-digit form: the stored and returned content carries the normalized token (e.g. `@551177776666` → `@5511977776666`) |
| Invalid token | Invalid or non-normalizable digits stay as **plain text**: a send never fails because of a mention |
| Where it works | In 1:1 chats and groups, in `text` and in the `caption` of `image`/`video`/`document` (`audio`/`sticker` have no caption) |
| Reusing a received token | The `@<number>` token you receive in `message.received` can be pasted back into a send: the mention works without any conversion |
| Quota | Mentioning someone **never** consumes message or contact quota |

After the send, the message carries the `mentions` structure
(a list of `{contact_id?, name?, number}`; `contact_id` and `name` are omitted
when the mention does not match a known contact) in
[`GET /v1/messages/{message_id}`](/en/messages/get/) and in the `data.mentions`
of the [`message.sent`/`message.replied`/`message.edited`](/en/messages/webhook/) events.
A literal `@<digits>` in the text is a mention **only** if it appears in that structure.

The same detection rules apply to `POST .../messages/{message_id}/reply`
(the reply's `text`/`caption`) and to `POST .../messages/{message_id}/edit` (the
new `text` of the edit replaces the message's **entire** set of mentions,
see [Edit and delete messages](/en/messages/edit-delete/#mentions-in-edits)).

## Possible errors

These are the main errors that can occur when sending messages, and how to read them:

| Status | Error code              | Description                                       |
| :----: | ----------------------- | ------------------------------------------------- |
| `400`  | `contact_not_found`     | The `contact_id` provided does not belong to the organization.  |
| `400`  | `contacts_not_enabled`  | Sending by `contact_id` is not set up.            |
| `400`  | `invalid_phone_number`  | The `to.number` provided is not a valid phone number in E.164 format (e.g. `+5511988887777`). |
| `400`  | `invalid_recipient`     | The recipient given in `to` could not be resolved to a sending address. Providing none, or more than one, of `number`, `group_id` and `contact_id` returns `422 validation_error`. |
| `400`  | `not_group_member`      | Your number is no longer a participant of the given `group_id`, see [Sending to a group](#sending-to-a-group). |
| `402`  | `feature_not_available` | Sending to a group (`to.group_id`) requires the `BUSINESS` plan or higher, see [Sending to a group](#sending-to-a-group). |
| `402`  | `subscription_inactive` | Subscription with a pending payment, ended, or with an expired trial (`details.status`). Blocks every send until the subscription is active again. |
| `402`  | `contact_quota_exceeded` | The current cycle's allowance of distinct contacts is used up, see [Quota and usage](/en/usage/quota/). |
| `403`  | `not_authorized`        | The API key is invalid or missing.                |
| `403`  | `insufficient_scope`    | The API key does not have the `messages:send` scope (the response includes `required_scope`). |
| `404`  | `number_not_found`      | The alias in the URL does not match any number registered in the account. |
| `404`  | `group_not_found`       | The `group_id` given in `to` was not found in the account. |
| `409`  | `number_not_connected` | The sending number is not connected to WhatsApp. Reconnect the number and try again. |
| `422`  | `validation_error`      | The request body is malformed or failed validation. The response includes `details.errors` with the rejected fields. |
| `422`  | `group_not_owned_by_number` | The `group_id` provided belongs to another number in the account, not to the alias in the URL path. |
| `422`  | `message_not_replyable` | *(only `POST .../messages/{message_id}/reply`)* The quoted message has not been sent to WhatsApp yet or has already been deleted. |
| `429`  | `messages_quota_exceeded` | The current cycle's message allowance is used up, see [Quota and usage](/en/usage/quota/). |
| `429`  | `send_rate_spacing`     | Sent before the minimum interval between messages for your plan, see [Usage limits](/en/messages/rate-limits/). |
| `429`  | `rate_limit_exceeded`   | The API's requests-per-second limit was exceeded. The other send protection limits (`messages_per_minute_limit_exceeded`, `recipients_per_day_limit_exceeded`, `warmup_limit_exceeded`, `duplicate_burst_blocked`, `reply_ratio_too_low`) have their own codes, see [Usage limits](/en/messages/rate-limits/#related-errors). |
| `500`  | `internal_error`        | Unexpected internal server error.                 |

## Message status

The status tells you how far the message has progressed. For full details on each status, see the [Status](/en/messages/status/) documentation.

<ApiResponse
  status={202}
  body={{
    message_id: 'msg_01993c5a1b24d3e9f01a2b3c4d5e6f70',
    status: { state: 'pending', at: '2025-07-16T10:00:00Z', error: null },
  }}
/>

The final outcome arrives by webhook with the `message.sent`, `message.delivered`, `message.read` or `message.send.failed` events.

## Security and privacy

All communication between your system and the Turbo Notify API happens exclusively over HTTPS, so data is always encrypted in transit.

To find out how long messages remain available for lookups and operations, see the [Retention](/en/messages/retention/) documentation.

## Rich content: location, contact, calendar and link button

`POST /v1/messages` accepts four rich content
variants besides `text`. Each variant has its own anchor field
inside the `content` object and reaches WhatsApp as the corresponding
native type (`locationMessage`, `contactMessage`, `eventMessage`).

| Field | Type | Required | Notes |
|---|---|---|---|
| `content.name` | string | yes | event title; up to 200 characters |
| `content.description` | string | no | up to 2000 characters |
| `content.start_at` | datetime | yes | ISO-8601 with time zone (anchor field of the `calendar` variant) |
| `content.end_at` | datetime | no | ISO-8601 with time zone; must be > `start_at` |
| `content.join_link` | string | no | `http://`/`https://` only |
| `content.location` | object | no | same format as the `location` object |
| `content.has_reminder` | bool | no | defaults to `false` |
| `content.reminder_offset_sec` | int | no | seconds before the event; only takes effect with `has_reminder=true` and is ignored, without an error, when `has_reminder` is `false` or absent |
| `content.extra_guests_allowed` | bool | no | defaults to `false` |

:::tip
WhatsApp calls this message type an "event". In Turbo Notify the variant is
named `calendar` so it is not confused with webhook events.
:::

:::caution[Personal WhatsApp accounts receive the event without a time]
The `calendar` variant (anchor field `start_at`) is a **WhatsApp Business** feature (`eventMessage`).
When the recipient has a **personal account** (not Business), WhatsApp
removes the start and end time (`startTime`/`endTime`) on delivery. The
recipient gets the message with the other details (`name`,
`description`, `join_link`, `location`), but **without a time**. The
matching `message.received` webhook keeps the `calendar` variant and
omits the `start_at` field. The message is not reclassified as
`unsupported`.

The send (`message.sent`) and the delivery status (`message.delivered` /
`message.read`) work normally; only the time on the event card is missing
on the recipient's phone. To avoid this, confirm the recipient's account
is WhatsApp Business before sending `calendar`, or use the `text` variant
with an ICS link when the recipient has a personal account and the time
matters.
:::

### Send a link button

A message with a button that opens a link. The anchor field is
`interactive_type`, always `"cta_url"`.

```json title="POST /v1/messages: link button"
{
  "to": { "number": "+5511988887777" },
  "content": {
    "interactive_type": "cta_url",
    "body": "Your order has shipped.",
    "footer": "Example Store",
    "url_button": { "display_text": "Track", "url": "https://example.com/tracking/123" }
  }
}
```

| Field | Type | Required | Notes |
|---|---|---|---|
| `content.interactive_type` | string | yes | always `"cta_url"` |
| `content.body` | string | yes | 1 to 1024 characters |
| `content.header` | object | no | `{ "type": "text", "text": "..." }`, `text` with 1 to 60 characters |
| `content.footer` | string | no | up to 60 characters |
| `content.url_button.display_text` | string | yes | 1 to 20 characters |
| `content.url_button.url` | string | yes | `http://` or `https://` URL |

### How it looks to the recipient

Each type appears in the recipient's WhatsApp with the native interface:
**location** with a map and a button to open it, **contact** with a card
that can be saved, **calendar** with an "Add to calendar" button,
**link button** with the button right below the text.

To see exactly how the matching `message.sent` event reaches your webhook,
open the [Webhook Inspector](https://webhook.turbonotify.com/).
The "Enriched" panel renders these types with dedicated cards.

## Sending to a group

To send to a group, the `to` field
takes the object `{ "group_id": "grp_..." }` instead of
`{ "number": "+5511988887777" }`, which is used for 1:1 chats. See
[Groups overview](/en/groups/overview/) for details of the model.

:::note[Requires the BUSINESS plan or higher]
Sending a message (or a typing indicator) to a `group_id` requires the
`groups:messages` feature, available from the `BUSINESS` plan up. On
`FREE`/`SOLO` you still **receive** group messages, **list groups**
(`GET /v1/numbers/{alias}/groups`) and look up their details. Only
**sending** to a group is blocked with `402`:

<ApiResponse
  status={402}
  body={{
    error: 'feature_not_available',
  }}
/>

See [Quota and usage](/en/usage/quota/#sending-to-groups-requires-the-business-plan-or-higher)
and [Group limitations](/en/groups/limitations/).
:::

```json title="POST /v1/messages: group"
{
  "to": { "group_id": "grp_e442553a56b14e2695f6acfd7d651b1a" },
  "content": {
    "text": "Good morning, team"
  }
}
```

The `to` field is polymorphic. It accepts exactly one of three forms (no `kind` or `type`):

| `to` form | Destination |
|---|---|
| `{ "number": "+5511988887777" }` | 1:1 message (a person) |
| `{ "group_id": "grp_..." }` | Group message |
| `{ "contact_id": "ct_..." }` | 1:1 message by Turbo Notify contact ID |

- The three forms are **mutually exclusive**. Send exactly one.
- `group_id` is the public `grp_{hex32}` identifier received in
  `message.received` webhooks/polling (`to.group_id`) or in the
  [group lifecycle](/en/groups/lifecycle-events/) events.
- The `content` object uses the same format as 1:1 sends (text, image,
  video, audio, document, sticker, location, contact, calendar,
  link button), with no differences.
- To quote a message inside the group, use the dedicated
  `POST /v1/numbers/{alias}/messages/{message_id}/reply` endpoint.

The response has the standard format (`message_id`, `status`). The matching
`message.sent` webhook uses `to.group_id` (the same value you sent in the
request); the envelope's `number_alias` identifies the number that sent it,
which helps you match received and sent messages in the same group.

:::caution[Your organization must be in the group]
Turbo Notify only sends to groups in which your number (main or extra) is
a participant. Trying to send to a `group_id` you are no longer in
returns 400 `not_group_member`. Join the group again through WhatsApp
(the `group.joined` webhook confirms it) and try again.
:::

:::tip[A message to a group counts once]
A message to a group counts as **1 recipient** toward the daily recipient
limit, no matter how many participants the group has. Contact quota
(`contact.quota.*`) is not affected: group participants do not become
contacts.
:::

## Sending by contact_id

Use `to.contact_id` to send to a contact Turbo Notify already knows, without providing the phone number.
Turbo Notify uses the number recorded for that contact.

```json
{
  "to": { "contact_id": "ct_a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4" },
  "content": { "text": "Hi, how are you?" }
}
```

:::tip[Getting the contact_id]
The `contact_id` (format `ct_{hex32}`) is returned in contact webhooks
(`contact.created`, `contact.name_changed`, `contact.picture_changed` and
`contact.first_messaged`) and by the `GET /v1/numbers/{alias}/contacts` endpoint.
:::
