```http title="Poll events"
GET /v1/events
```

Event polling is **account-level** and stays **top-level** — it was not nested
under the number. Each event envelope carries **`number_alias`** (below
`organization_id`) for events tied to a number; use it for subsequent by-id calls.

An optional **`number_alias`** query parameter restricts the response to a single
number's events:

```bash
curl "https://api.turbonotify.com/v1/events?number_alias=main" \
  -H "Authorization: Bearer tn_live_..."
```

The event `data` is **byte-identical** to the matching webhook delivery, so
polling and webhooks are interchangeable. `number_alias` is omitted only on
`storage.*`; every `*.quota.*` family (including `message.quota.*`, per-number
since ADR 2026-07-02) carries it.

Parity includes **`data.mentions`** (since 2026-07-03): when a message mentions
someone, the polled `message.received`/`replied`/`sent`/`edited` items return
the same `mentions` list — and the same mention-aware `preview` (each mention
token counts as 1 character) — byte-identical to the webhook delivery.
