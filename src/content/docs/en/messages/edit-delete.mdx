Both operations act on a message you **already sent**. The `message_id` is the same `msg_{hex32}` returned by the original send or seen in webhooks/polling. Both return **202 Accepted** immediately; the actual result arrives asynchronously via webhook.

Use `POST /v1/messages/{id}/edit` and `POST /v1/messages/{id}/delete` for the main number. For extra numbers, use `POST /v1/numbers/{alias}/messages/{id}/edit` and `.../delete`.

**Required scope:** `messages:send`

Before editing or deleting, Turbo Notify opens the conversation the way a person would: the number shows as online, the unread messages in the chat the target message belongs to are marked as read, and only then does the edit or deletion happen. See [Mark as read](/en/other-features/mark-as-read/).

## Edit a message

Replaces the text of a text message you already sent (native WhatsApp editing: the conversation history shows "edited").

      -H "Authorization: Bearer YOUR_KEY" \
      -H "Content-Type: application/json" \

### Request body

| Field | Type | Required | Notes |
|---|---|---|---|
| `text` | string | yes | 1 to 65,536 characters. The only accepted field: the body is strict (any other field returns `422`). |

### Response (202)

<ApiResponse
  status={202}
  body={{
    message_id: 'msg_01993c5a1b24d3e9f01a2b3c4d5e6f70',
    status: { state: 'pending', at: '2026-06-01T13:05:01Z', error: null },
  }}
/>

The actual result arrives via the `message.edited` webhook (success) or
`message.edit.failed` (failure, with an `error` object). After the edit,
`GET /v1/numbers/{alias}/messages/{id}` already returns the updated text.

### Mentions in edits

The new `text` of the edit also goes through `@<number>` mention detection,
with the same rules as [Mentions (@mentions)](/en/messages/send/#mentions-mentions).
The edit **replaces the message's whole set of mentions**: the `mentions`
returned by `GET /v1/numbers/{alias}/messages/{id}` (and the `data.mentions` of the
`message.edited` webhook) then reflects only the tokens present in the **new**
text. An edit that removes every `@<number>` from the original text makes
`mentions` disappear from the response.

### Response (202)

<ApiResponse
  status={202}
  body={{
    message_id: 'msg_01993c5a1b24d3e9f01a2b3c4d5e6f70',
    status: { state: 'pending', at: '2026-06-01T13:06:01Z', error: null },
  }}
/>

The actual result arrives via the `message.deleted` webhook (success) or
`message.delete.failed` (failure, with an `error` object).

After a successful deletion, `GET /v1/numbers/{alias}/messages/{id}` no longer
returns the original content, both for whoever deleted it and for every
recipient of the message. The message's `content_type` **does not change**: what
changes is the content of the matching structured field:

| Original `content_type` | Affected field | Value after deletion |
| --- | --- | --- |
| `text` | `text` | `""` (empty string) |
| `image` / `video` / `audio` / `document` / `sticker` | `image` / `video` / `audio` / `document` / `sticker` | `{"kind": "unavailable", "reason": "deleted"}`: the media is no longer reachable via signed URL |
| `location` | `location` | `{"kind": "unavailable", "reason": "deleted"}` |
| `calendar` | `calendar` | `{"kind": "unavailable", "reason": "deleted"}` |
| `contact` | `contact` | `{"kind": "unavailable", "reason": "deleted"}` |
| `interactive` | `interactive` | `{"kind": "unavailable", "reason": "deleted"}` |

The same `{"kind": "unavailable", "reason": "deleted"}` object is used in
every non-text case, including `location`/`calendar`/`contact`/
`interactive`, which carry no media of their own, so that you have
**a single predictable format** for "this content is no longer
available", instead of handling each `content_type`
differently.

## Possible errors

Both endpoints share the same set of errors:

| Status | Error code               | Description                                                    |
| :----: | ------------------------ | -------------------------------------------------------------- |
| `400`  | `message_not_editable`   | *(edit only)* The message was **received** (sent by someone else), was sent from the phone itself (`origin: "native"`), is not a text message, has not been sent yet, was already deleted, or its current status (`failed`, for example) does not allow editing. |
| `400`  | `message_not_deletable`  | *(delete only)* The message was **received** (sent by someone else), was sent from the phone itself (`origin: "native"`), has not been sent yet, was already deleted, or its current status does not allow deletion. |
| `401`  | `not_authenticated`      | The API key is invalid or missing.                             |
| `403`  | `insufficient_scope`     | The API key does not have the `messages:send` scope (the response includes `required_scope`). |
| `404`  | `number_not_found`       | The alias in the URL does not match any registered number.     |
| `404`  | `not_found`              | The message was not found, belongs to another organization, is outside your plan's [content retention window](/en/messages/retention/), or (on the nested route `/numbers/{alias}/messages/...`) belongs to a number other than the alias in the URL: all of these cases return the same response, with no distinction. |
| `404`  | `message_not_found`      | *(only on the shortcut route without `{alias}`, `POST /v1/messages/{id}/edit`\|`/delete`)* The `message_id` exists but belongs to an extra number, not to the main number. |
| `404`  | `request_not_found`      | The message could no longer be found while the edit or deletion was being processed. Look up the message with `GET` and, if it still exists, try again. |
| `409`  | `number_not_connected` | The number that sent the message is not connected to WhatsApp. Reconnect the number and try again. |
| `500`  | `internal_error`         | Unexpected internal server error.                              |

## Which messages can be edited or deleted

Three criteria, and all three must be met: any one that fails is
rejected **synchronously**, with `400 message_not_editable` /
`400 message_not_deletable`, before any contact with WhatsApp:

1. **Sent by this number, through this API**: the message must have been
   sent through the Turbo Notify API by this number (`direction: "outbound"`
   and `origin: "tn"`). Two kinds of message are excluded by this criterion:
   - **Received** messages: messages a contact or participant
     sent **to** you. They belong to the sender, not to you, and
     WhatsApp does not let you edit or revoke a message you did not
     send.
   - Messages typed **on the phone itself** (`origin: "native"`),
     sent outside the API, directly on the device. Turbo Notify is not
     the client that originated that message, so it cannot edit
     or revoke it either.
2. **Content type** *(edit only)*: WhatsApp only allows editing
   **text** messages. Editing a media message (image, video,
   audio, document, sticker) or another structured type (location,
   calendar, contact, interactive) fails with `400 message_not_editable`.
3. **Status**: only messages that are already `sent`, `delivered` or
   `read`, and that have not been deleted yet, are accepted. Messages still
   `pending`, already `failed`, or already deleted return
   `400 message_not_editable` / `400 message_not_deletable`.
