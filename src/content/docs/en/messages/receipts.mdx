After a message is sent, WhatsApp returns delivery and read confirmations. The receipt history records these confirmations: `delivered` (delivered to the device) and `read` (read by the recipient), in ascending chronological order.

## List receipts

To list a message's receipt history, make a `GET` request with the `message_id` returned when you sent it.

**Endpoint:** `GET /v1/messages/{message_id}/receipts` for the main number. For extra numbers, use `GET /v1/numbers/{alias}/messages/{message_id}/receipts`, where `{alias}` is the message's `number_alias`.

**Required scope:** `messages:read`

**Path parameters:**

| Parameter    | Type   | Description                             |
| ------------ | ------ | --------------------------------------- |
| `alias` | string | *(extra number route only)* Alias of the number the message belongs to. |
| `message_id` | string | Public message identifier (`msg_{hex32}`) |

## Response structure

| Field                    | Type    | Description                                                        |
| ------------------------ | ------- | ------------------------------------------------------------------ |
| `message_id`             | string  | Public message identifier.                                         |
| `receipts`               | array   | List of status changes, in ascending chronological order.          |
| `receipts[].from`            | object  | Who confirmed the receipt. Omitted when WhatsApp gives no information about who confirmed it. |
| `receipts[].from.contact_id` | string  | Public contact identifier (`ct_{hex32}`). Omitted when not available. |
| `receipts[].from.name`       | string  | WhatsApp display name (personal data, under your organization's responsibility). Omitted when not available. |
| `receipts[].from.number`     | string  | E.164 number without `+` of who confirmed the receipt. Omitted when WhatsApp does not reveal the number of who confirmed it. |
| `receipts[].status`      | string  | Status reached in this change (`delivered` or `read`).             |
| `receipts[].at`          | string  | ISO 8601 date and time when the status was recorded.               |

## Status table

| Status      | Description                                                                 |
| ----------- | --------------------------------------------------------------------------- |
| `delivered` | Confirmation from WhatsApp that the message was delivered to the device.    |
| `read`      | Confirmation from WhatsApp that the recipient read the message.             |

> **Note:** Only confirmations sent by WhatsApp (`delivered` and `read`) are recorded as receipts. The `sent` status (sent to WhatsApp) can be checked with [`GET /v1/numbers/{alias}/messages/{id}/status`](/en/messages/status/).

## Requires the BUSINESS plan or higher

The detailed receipt history (`GET .../messages/{id}/receipts`) requires the `read_receipts` feature, available from the `BUSINESS` plan up. Organizations on `FREE`/`SOLO` receive:

<ApiResponse
  status={402}
  body={{
    error: 'feature_not_available',
  }}
/>

This restriction applies to both routes (the nested `/v1/numbers/{alias}/messages/{id}/receipts` and the short `/v1/messages/{id}/receipts` route of the main number). The restriction does **not** affect the overall message status: [`GET .../messages/{id}/status`](/en/messages/status/) stays available on **every** plan, including `FREE`/`SOLO`. Only the **detailed** history, change by change, requires BUSINESS or higher.

See [Quota and usage](/en/usage/quota/) for the limits and restrictions of each plan.

## Possible errors

| Status | Error code               | Description                                                                    |
| :----: | ------------------------ | ------------------------------------------------------------------------------ |
| `402`  | `feature_not_available` | Organization on the `FREE`/`SOLO` plan: the receipt history requires `BUSINESS` or higher. |
| `401`  | `not_authenticated`     | The API key is invalid or missing.                                             |
| `403`  | `insufficient_scope`    | The API key does not have the `messages:read` scope.                           |
| `404`  | `not_found`             | The message was not found, belongs to another organization, is outside your plan's [content retention window](/en/messages/retention/), or (on the nested route `/numbers/{alias}/messages/.../receipts`) belongs to a number other than the alias in the URL: all of these cases return the same response, with no distinction. |
| `404`  | `message_not_found`     | *(only on the shortcut route without `{alias}`, `GET /v1/messages/{id}/receipts`)* The `message_id` exists but belongs to an extra number, not to the main number. |
| `404` | `number_not_found` | *(only on the route with `{alias}`)* The alias in the URL does not match any registered number. |
| `500`  | `internal_error`        | Unexpected internal server error.                                              |
