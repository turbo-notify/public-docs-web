List a number's messages (sent and received), paginated by cursor, newest first. Each item is a summary: for the full body of a specific message, use [Get a message](/en/messages/get/).

Use `GET /v1/messages` for the main number. For extra numbers, use `GET /v1/numbers/{alias}/messages`, where `{alias}` is the `number_alias` present in the webhook/polling envelope.

**Required scope:** `messages:read`

## Query parameters

| Parameter | Type | Description |
| --------- | ---- | ----------- |
| `cursor` | string | Opaque token returned in `cursor` by the previous page. Absent = first page. |
| `limit` | int | Number of items per page. Range: 1 to 200. Default: 50. |

## Response fields

| Field | Type | Description |
| ----- | ---- | ----------- |
| `data` | array | Page of messages, newest first |
| `cursor` | string\|null | Opaque token for the next page; `null` when there are no more items |
| `has_more` | boolean | `true` if more pages are available |
| `data[].id` | string | Public identifier of the message (`msg_` + 32 hex) |
| `data[].number_alias` | string | Identifier of the number the message belongs to: `"main"` or the alias of an extra number |
| `data[].direction` | string | `outbound` (sent) or `inbound` (received) |
| `data[].content_type` | string | `text`, `image`, `audio`, `video`, `document`, `sticker`, `location`, `calendar`, etc. |
| `data[].preview` | string | Opening excerpt of the content, never splitting an emoji or accented character (same value as `GET /v1/numbers/{alias}/messages/{id}`) |
| `data[].at` | string | ISO 8601: the **stable occurrence time** of the message (outbound: actual send; inbound: receipt). It does not move as the message progresses `sent → delivered → read`. |
| `data[].status` | object | `{state, at, error}`: current delivery state and the timestamp of that transition. `error` is filled in (`{code, message, hint}`) when `state` is `"failed"` and is `null` in every other state, on both routes. |

:::note[No `mentions` in the list]
Unlike [Get a message](/en/messages/get/), the items in this list
**never** include the `mentions` field: each item is a lean summary.
To see the mentions of a specific message, use
`GET /v1/numbers/{alias}/messages/{id}`.
:::

## Ordering and pagination

- Items come in the order Turbo Notify accepted each message (newest
  first), not strictly by `at`. For most messages the two match; for
  outbound sends, `at` (the actual send time) can be a few seconds after
  acceptance, because the send simulates typing time before it reaches
  WhatsApp. That is why `at` can be slightly out of order within a page.
  The page is always complete, with no gaps.
- Pagination uses `cursor`: pass the returned value as `cursor` on the
  next call until `has_more` is `false`.
- Messages outside your plan's [content retention window](/en/messages/retention/)
  are **filtered out**: they simply do not appear in the page
  (unlike `GET .../messages/{id}`, which returns 404 for a message
  outside the window).

## Possible errors

| Status | Error code             | Description                                          |
| :----: | ---------------------- | ---------------------------------------------------- |
| `401`  | `not_authenticated`    | The API key is invalid or missing.                   |
| `403`  | `insufficient_scope`   | The API key does not have the `messages:read` scope (the response includes `required_scope`). |
| `404`  | `number_not_found`     | The alias in the URL does not match any registered number. |
| `422`  | `validation_error`     | A query parameter failed validation: for example, `limit` outside the 1 to 200 range. The response includes `details.errors` with the rejected fields. |
| `500`  | `internal_error`       | Unexpected internal server error.                    |
