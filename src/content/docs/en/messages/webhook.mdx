Turbo Notify delivers events to your configured webhook endpoint as HTTP POST.
Each event envelope carries **`number_alias`** (below `organization_id`) for
events tied to a number.

To fetch the full message body referenced by a `message.*` event, call the
number-scoped get endpoint using the alias from the envelope:

```http title="Fetch the full message"
GET /v1/numbers/{alias}/messages/{id}
```

where `{alias}` is the envelope's `number_alias` and `{id}` is the `msg_…` id.
The webhook `data` is **byte-identical** to the equivalent `GET /v1/events`
item. `number_alias` is omitted only on `storage.*` and `media.unavailable`
(the events with no single owning number); every `*.quota.*` family (including
`message.quota.*`, per-number since 2026-07-02) carries it.

When a message mentions someone (since 2026-07-03), the **body-bearing** events
— `message.received`, `message.replied`, `message.sent`, `message.edited` —
carry an optional **`data.mentions`** array (`{contact_id?, name?, number}`
items; absent when there are no mentions; on `message.edited` it is the set
re-extracted from the new text). Each mention token counts as exactly
**1 character** toward the ~50-char `data.preview` and the crop never splits a
token; a literal `@digits` not listed in `mentions` is plain text. Not present
on `delivered`/`read`/`deleted`/`reacted` or `*.failed` events.
