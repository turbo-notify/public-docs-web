Changes that affect your integration are listed here, newest first. Changes that need action on your side are marked as such.

## October 2026: launch

- **WhatsApp API**: sending text, media, location, contact, calendar event and link button; replies, reactions, editing and deleting; delivery and read receipts; contacts and groups per number. See the [Quickstart](/en/guides/quickstart/).
- **Events** by signed [webhook](/en/messages/webhook/) or by [polling](/en/messages/polling/), in the same format.
- **MCP server** with 32 tools for AI agents, authenticated with your key. See [Build an AI agent](/en/guides/ai-agent/).
- **Resale**: extra numbers with `external_id`, `status` and `external_id` filters on the number list, `external_id` on every `number.*` event and the **Resale** key template. See [Resell to your customers](/en/guides/resale/).
- **Interactive API reference**, [error code index](/en/reference/errors/) and [Insomnia collection](/en/reference/api/#insomnia-collection).
- **Authentication errors**: a missing, malformed, unknown, revoked or expired key answers `401 not_authenticated`, with the `WWW-Authenticate: Bearer` header; `403` is for a valid key without permission (`insufficient_scope`). Before launch these cases answered `403 not_authorized`: if your test integration handled that code, switch it to the `401`. See the [error code index](/en/reference/errors/).
- **Quota warnings**: `message.quota.warning` and `contact.quota.warning` carry the threshold reached in `data.threshold_percent` (`80`, `90` or `95`, in percent). Before launch the field was called `threshold_bps`, with the same values: if your test integration read that name, switch to `threshold_percent`. See [Message quota events](/en/webhooks/message-quota-events/).
- **New extra number and pairing** (adjust if your test integration used the old names): the body of `POST /v1/numbers` takes the phone as `phone_number` (the name `phone` is no longer accepted and answers `422`), and the body of `POST /v1/numbers/{alias}/pair` only accepts `method: "pairing_code"` (`"qr"` used to answer with no effect and now answers `422`). See [Add numbers](/en/numbers/add/) and [Pairing](/en/numbers/pairing/).
- **Failures of supporting services**: when the API cannot reach a service it depends on, the answer is `503 service_unavailable`; when an outside service answers with an error (for example, the payment processor when you add an extra number), the answer is `502 integration_error`. Before, some cases returned internal codes that are not part of the contract. See the [error code index](/en/reference/errors/).
- **MCP server**: opening a streaming connection without a key answers `401 not_authenticated`, with `WWW-Authenticate: Bearer`, as the API does (the code used to be `unauthorized`). See [MCP server](/en/general/mcp-server/).
- **Audio transcription**: when the transcription provider configured for your account is not supported, `data.transcription.reason` is `provider_not_supported` (before launch it was `no_adapter`). The other `reason` values are unchanged. See [Get a message](/en/messages/get/).
- Documentation in Portuguese and English.
