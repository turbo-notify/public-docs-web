Pairing is the moment the WhatsApp of the number starts recognizing Turbo
Notify as a linked device. After you [add the extra
number](/en/numbers/add/), whoever has its phone at hand types a **pairing
code** in WhatsApp. Through the API, extra numbers always pair with a pairing
code. The main number is paired in the dashboard.

If you offer WhatsApp numbers to your own customers, the person typing the
code is your customer, on your screen. This page shows how to build that
screen so they can finish on their own, even when something goes wrong.

## How it works

1. You request a code with `POST /v1/numbers/{alias}/pair`. The number
   moves to `status: "pairing"`.
2. Within a few seconds the code is available in the `pairing` block of
   `GET /v1/numbers/{alias}`.
3. On the number's phone, the person opens WhatsApp at **Linked devices >
   Link a device > Link with phone number instead** and types the code.
4. The number moves to `status: "connected"` (or `"failed"`, with the reason
   in `reason`).

Once paired, the number shows up under **Linked devices** on the phone with
the name of your organization, so the person recognizes the connection and
does not remove it by mistake.

## Request the code

The request body is optional. If you send `method`, the only accepted value is `"pairing_code"`: an extra number is always paired with a code. Any other value answers `422`.

## Show the code

Poll `GET /v1/numbers/{alias}` while `status` is `"pairing"`. When the code
is ready, the `pairing` block is filled in:

<ApiResponse
  status={200}
  body={{
    contact_id: null,
    name: null,
    type: 'extra',
    alias: 'vendas_sp',
    number: '5511988887777',
    status: 'pairing',
    at: '2026-09-28T14:00:00Z',
    description: null,
    external_id: null,
    scheduled_deletion_at: null,
    reason: null,
    pairing: {
      method: 'pairing_code',
      data: 'Z5X7-LTYL',
      expires_at: '2026-09-28T14:02:40Z',
    },
  }}
/>

- `pairing.data` is the code, 8 characters, shown with a hyphen.
- `pairing.expires_at` is when it stops being valid: use it for the countdown.
- While the code is still being generated, `pairing` is `null`.

## Mistyped code

If the code is mistyped on the phone, WhatsApp invalidates that code right
away: not even the correct code is accepted afterwards. WhatsApp does not
report this error to anyone, so your screen must offer a new code at any
time.

To generate a new code, call `POST /v1/numbers/{alias}/pair` again while the
number has `status: "pairing"`. The previous code is discarded, the `pairing`
block goes back to `null` and then carries the new code. Always show the
latest code. The same applies when the code expires.

## The WhatsApp of the registered number

Pairing must be completed in the WhatsApp of the registered number. If
another WhatsApp uses the code, the pairing is refused, the device is
unlinked from that other WhatsApp and the number ends up with
`status: "failed"` and `reason: "paired_phone_mismatch"`. To try again,
request a new code and complete the pairing on the phone of the registered
number.

## Pairing result

| Outcome | Through status | Through webhook |
| ------- | -------------- | --------------- |
| Succeeded | `status: "connected"` | [`number.connected`](/en/messages/webhook/) |
| Failed | `status: "failed"` and the reason in `reason` | [`number.connect.failed`](/en/messages/webhook/), with the same `reason` |

The code itself is only delivered by the status lookup: since it is a
short-lived credential, it is not sent in webhooks.

### Failure reasons

| `reason` | What to tell your customer |
| -------- | -------------------------- |
| `pairing_timeout` | The code expired before it was used. Get a new code. |
| `paired_phone_mismatch` | The code was used on another WhatsApp. Use the phone of the registered number. |
| `phone_already_bound` | This number is already in use in the account. |
| `main_number_not_connected` | The account's main number must be connected first. Reconnect the main number and try again. |
| `code_generation_failed` | WhatsApp could not generate the code right now. Try again shortly. |
| `connection_lost` | The number lost its connection to WhatsApp. Pair it again. |
| `pairing_failed` | The pairing could not be completed. Try again. |

New reasons may be added. Treat a value you do not recognize as
`pairing_failed`.

## Recommended pairing experience

A pairing screen that handles the common cases on its own:

1. **Request the code** with `POST /v1/numbers/{alias}/pair`.
2. **Poll the status every 2 seconds** while `status` is `"pairing"`. With
   `pairing` filled in, show `pairing.data` and the countdown to
   `pairing.expires_at`. With `pairing` `null`, show "generating code".
3. **Keep "Get a new code" always visible**, not only when the code expires:
   it is the way out of a mistyped code. The button calls
   `POST /v1/numbers/{alias}/pair` again.
4. **Finish on the result**: `connected` shows success; `failed` shows the
   message for the `reason` and offers to try again.
5. **Respect the attempt limit**: on a `429`, show how long is left from the
   `Retry-After` header instead of repeating the call.

<Tabs>
  <TabItem label="Node">
    ```js title="pairing.js"
    const API = 'https://api.turbonotify.com/v1/numbers';
    const headers = { 'Authorization': 'Bearer YOUR_KEY' };

    // Called when the screen opens and by the "Get a new code" button.
    async function requestCode(alias) {
      const res = await fetch(`${API}/${alias}/pair`, { method: 'POST', headers });
      if (res.status === 429) {
        return { waitSeconds: Number(res.headers.get('Retry-After')) };
      }
      return { waitSeconds: 0 };
    }

    // Called every 2 seconds while the screen is open.
    async function poll(alias) {
      const res = await fetch(`${API}/${alias}`, { headers });
      const number = await res.json();
      if (number.status === 'connected') return { screen: 'success' };
      if (number.status === 'failed') return { screen: 'failure', reason: number.reason };
      if (number.pairing) {
        return { screen: 'code', code: number.pairing.data, expiresAt: number.pairing.expires_at };
      }
      return { screen: 'generating' };
    }
    ```
  </TabItem>
  <TabItem label="Python">
    ```python title="pairing.py"
    import requests

    API = "https://api.turbonotify.com/v1/numbers"
    HEADERS = {"Authorization": "Bearer YOUR_KEY"}


    def request_code(alias: str) -> int:
        """Called when the screen opens and by the "Get a new code" button.

        Returns how many seconds to wait before allowing another request.
        """
        res = requests.post(f"{API}/{alias}/pair", headers=HEADERS)
        if res.status_code == 429:
            return int(res.headers["Retry-After"])
        return 0


    def poll(alias: str) -> dict:
        """Called every 2 seconds while the screen is open."""
        number = requests.get(f"{API}/{alias}", headers=HEADERS).json()
        if number["status"] == "connected":
            return {"screen": "success"}
        if number["status"] == "failed":
            return {"screen": "failure", "reason": number["reason"]}
        if number["pairing"]:
            return {
                "screen": "code",
                "code": number["pairing"]["data"],
                "expires_at": number["pairing"]["expires_at"],
            }
        return {"screen": "generating"}
    ```

## Attempt limit

Each `POST /v1/numbers/{alias}/pair` asks WhatsApp for a new code and
triggers a notification on the number's phone. Too many requests in a row
make WhatsApp itself block new codes for that number for a while. To protect
the number, pairing accepts up to **10 requests per minute per number** and
**30 per minute per account**. Above that the response is
`429 pairing_rate_limited`, with the `Retry-After` header in seconds:

<ApiResponse
  status={429}
  headers={{ 'Retry-After': '42' }}
  body={{
    error: 'pairing_rate_limited',
  }}
/>

## Possible errors

### Request the code (`POST /v1/numbers/{alias}/pair`)

| Status | Error code | Description |
| :----: | ---------- | ----------- |
| `402`  | `subscription_inactive` | The organization's subscription is not active (the response includes `details.status`). |
| `402`  | `feature_not_available` | The current plan does not include extra numbers. |
| `403`  | `main_number_pair_not_allowed` | The main number is paired in the dashboard. |
| `404`  | `extra_number_not_found` | The alias does not exist in the account. |
| `409`  | `already_paired_or_connected` | The number is already paired or connected. |
| `429`  | `pairing_rate_limited` | Attempt limit reached: wait `Retry-After` seconds. |

### Cancel (`POST /v1/numbers/{alias}/cancel-pairing`)

| Status | Error code | Description |
| :----: | ---------- | ----------- |
| `402`  | `feature_not_available` | The current plan does not include extra numbers. |
| `404`  | `extra_number_not_found` | The alias does not exist in the account. |
| `409`  | `not_pairing` | The number does not have `status: "pairing"`. |

Both routes also return `401 not_authenticated` (invalid or missing key) and
`403 insufficient_scope` (missing the `numbers:write` scope).
