Disconnect an extra number that is already paired to stop using it for a while, and reconnect it whenever you want to come back, without pairing again. Disconnected numbers stay registered in the account, but cannot be used as a sender. For the first link to WhatsApp, see [Pairing](/en/numbers/pairing/).

## Billing

Disconnected extra numbers keep being charged while they are registered. To stop the charge, you need to remove the number. See the details in [Extra number billing](/en/numbers/billing/).

## In the dashboard

Open the <DashboardLink path="/numbers">Numbers</DashboardLink> page in the dashboard to disconnect or reconnect numbers with one click.

## Reconnect

To reconnect a disconnected extra number, make a POST request to the connect endpoint with the number's alias in the URL.

:::caution[May trigger a charge]
If the extra number has a scheduled deletion, this call cancels the deletion. When the number was created before the start of the current billed cycle, the activation fee is charged again to bring it back. See [Extra number billing](/en/numbers/billing/).
:::

The response only confirms that the **transition was accepted**: the number
moves to `connecting` (`at` is empty in this call). The final status
(`connected` or `failed`) arrives through the `number.connected` /
`number.connect.failed` webhook, or by checking
[Extra number status](/en/numbers/status/).

<ApiResponse
  status={200}
  body={{
    status: 'disconnecting',
    at: '',
  }}
/>

`disconnecting` is an **acceptance confirmation** literal that only this
response uses, unlike `connecting`: it is not one of the values in the
[Status table](/en/numbers/status/#status-table) and does not appear in
`GET /v1/numbers/{alias}` (which, right after this call, still shows the
previous status until Turbo Notify finishes disconnecting). The final status
(`disconnected`) arrives through the `number.disconnected` webhook, or by
checking [Extra number status](/en/numbers/status/).

:::note[Main number connection]
The main number has its own routes, without `{alias}` in the path and with a
simpler response (only `alias` and `status`, no `at` field):

- `POST /v1/numbers/main/connect` → `202 Accepted`, `{"alias": "main", "status": "connecting"}`
- `POST /v1/numbers/main/disconnect` → `202 Accepted`, `{"alias": "main", "status": "disconnecting"}`

Neither depends on the plan: they are always available. Both return
`422 no_main_number_configured` when the account has no main number. On
connect: `422 main_number_not_paired` when the number exists but has not
finished pairing (pair it in the dashboard first), `409 already_connected`
and `409 already_connecting`. On disconnect: `409 already_disconnected` when
the number is already disconnected (nothing to do, the goal is already met).
:::

## Possible errors

### Reconnect (`POST /v1/numbers/{alias}/connect`)

| Status | Error code                   | Description                                                   |
| :----: | ---------------------------- | ------------------------------------------------------------- |
| `400`  | `no_payment_method`          | The number had a scheduled deletion and reactivation requires a charge, but the organization has no payment method on file. The deletion stays scheduled. |
| `402`  | `subscription_inactive`      | The organization's subscription is `past_due`, `terminated`, `pending` or its trial period has expired (the response includes `details.status`). |
| `402`  | `feature_not_available`      | The current plan does not support extra numbers.              |
| `402`  | `payment_declined`           | The reactivation charge was declined. The deletion stays scheduled. |
| `402`  | `payment_requires_authentication` | The payment method requires re-authentication (3DS). The deletion stays scheduled. |
| `403`  | `no_device_link`             | The extra number has no active link to WhatsApp (inconsistent state). |
| `403`  | `extra_number_not_paired`    | The extra number has not finished pairing. Call `POST /v1/numbers/{alias}/pair` first. |
| `404`  | `extra_number_not_found`     | The alias does not match any registered number.               |
| `409`  | `already_connected`          | The extra number is already connected.                        |
| `409`  | `already_connecting`         | A connection attempt is already in progress.                  |
| `500`  | `internal_error`             | Unexpected internal server error.                             |
| `503`  | `payment_gateway_unavailable` | The reactivation charge could not be confirmed in time. Try again. |

### Disconnect (`POST /v1/numbers/{alias}/disconnect`)

| Status | Error code               | Description                                                   |
| :----: | ------------------------ | ------------------------------------------------------------- |
| `402`  | `feature_not_available`  | The current plan does not support extra numbers.              |
| `404`  | `extra_number_not_found` | The alias does not match any registered number.               |
| `409`  | `already_disconnected`   | The extra number is already disconnected (nothing to do).     |
| `500`  | `internal_error`         | Unexpected internal server error.                             |

Both routes also return `401 not_authenticated` (invalid or missing key) and
`403 insufficient_scope` (missing the `numbers:write` scope, the response
includes `required_scope`) like any other authenticated endpoint.
