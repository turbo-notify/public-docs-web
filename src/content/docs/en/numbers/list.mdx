Without filters, `GET /v1/numbers` returns **all** the numbers registered in
the organization: the **main number first**, followed by the extra numbers in
creation order.

:::note[`status.at` follows the current status]
`status.at` is the moment the number **entered its current status**: it
updates on every transition (pairing, connection, connection drop,
reconnection, failure, revocation). A `disconnected`, `failed`,
`reconnecting` (and so on) number reports the moment of that transition, not
an outdated connection timestamp.

During an automatic reconnection (an internal move of the connection), the
number shows as `reconnecting` and, if it does not come back within about one
minute, as `disconnected`; in both cases `status.at` is the moment it went
offline. See [Status](/en/numbers/status/).

A newly added number that has not been paired yet (`status: "pending"`, like
`condominio_3` in the example above) has the time it was added in
`status.at`.

The exception is `status: "pending_deletion"` (extra numbers only):
`status.at` holds the time of the **scheduled deletion**, not a connection
transition.
:::

**Required scope:** `numbers:read`

## Filters

Two optional query string filters narrow the list:

| Parameter | Description |
| --------- | ----------- |
| `status` | Only the numbers in this status. Accepts one of the values in the [Status table](/en/numbers/status/#status-table), for example `?status=failed`. A value outside the table answers `422 validation_error`. |
| `external_id` | Only the number with this `external_id`, exact match, for example `?external_id=customer-4821`. |

Both filters together combine: the number must match both. The main number
is listed only when it matches the filters.

```bash title="turbo-notify.sh"
# Numbers in the account whose pairing failed
curl -X GET \
  "https://api.turbonotify.com/v1/numbers?status=failed" \
  -H "Authorization: Bearer YOUR_KEY"

# The number of your customer 4821
curl -X GET \
  "https://api.turbonotify.com/v1/numbers?external_id=customer-4821" \
  -H "Authorization: Bearer YOUR_KEY"
```

## Response fields

| Field | Type | Description |
| ----- | ---- | ----------- |
| `data` | array | List of the account's numbers (main + extra) |
| `cursor` | string\|null | Always `null`: this route does not paginate |
| `has_more` | boolean | Always `false`: this route returns all numbers in a single page |
| `data[].contact_id` | string\|null | Public identifier (`ct_…`) of the number's own contact; `null` until resolved |
| `data[].name` | string\|null | Name of the number's WhatsApp account (captured on connection); `null` until a connection has been established |
| `data[].type` | string | `"main"` for the main number (always the first item) or `"extra"` for extra numbers |
| `data[].alias` | string | Unique identifier of the number in the account (`"main"` for the main number) |
| `data[].number` | string | Phone number in E.164 digits (no `+`) |
| `data[].description` | string\|null | Free-form description you set |
| `data[].external_id` | string\|null | Your own identifier for this number, set when [adding](/en/numbers/add/) or [updating](/en/numbers/update/) it; `null` when not set |
| `data[].status` | object | `{status, at, reason?}`: current state of the number |
| `data[].status.status` | string | `pending`, `pairing`, `inactive`, `connecting`, `connected`, `disconnected`, `reconnecting`, `failed`, `revoked` or `pending_deletion`, see [Status table](/en/numbers/status/#status-table) |
| `data[].status.at` | string | ISO 8601 timestamp of the moment the number **entered its current status** (`data[].status.status`): updates on every transition. Exception: with `status: "pending_deletion"`, it is the time of the scheduled deletion. |
| `data[].status.reason` | string\|null | Failure reason when `status.status` is `"failed"` (same values as [Failure reasons](/en/numbers/status/#failure-reasons)); `null` in any other status. |

## Possible errors

`GET /v1/numbers` does not depend on the plan: the main number can always be
listed, and the list returns any extra number that already exists in the
account regardless of the current plan.

**Listing is the only extra number operation available on every plan**. All
the others ([add](/en/numbers/add/#possible-errors),
[check status](/en/numbers/status/#possible-errors),
[connect/disconnect](/en/numbers/activation/#possible-errors) and
[remove](/en/numbers/remove/#possible-errors)) require a plan that supports
extra numbers and return `402 feature_not_available` otherwise. In an account
that moved to a plan without extra numbers, you can still see the existing
extra numbers, but you cannot manage them.

| Status | Error code              | Description                                         |
| :----: | ----------------------- | --------------------------------------------------- |
| `403`  | `not_authorized`        | The API key is invalid or missing.                  |
| `403`  | `insufficient_scope`    | The API key does not have the `numbers:read` scope (the response includes `required_scope`). |
| `422`  | `validation_error`      | The `status` filter has a value that is not in the [Status table](/en/numbers/status/#status-table). |
| `500`  | `internal_error`        | Unexpected internal server error.                   |
