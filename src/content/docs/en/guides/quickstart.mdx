This guide takes you from sign-up to a first message sent through the API and a reply received back. There are five steps, and the second one (connecting your WhatsApp number) is the one people skip most: without it, every send answers `409 number_not_connected`.

You need a phone with WhatsApp on the number that will send the messages. Turbo Notify connects to it as a linked device, the same way WhatsApp Web does, and the phone keeps working as usual.

:::caution[Not the official Meta API]
Turbo Notify connects your number as a linked device; it does not use the official WhatsApp Business API from Meta. The platform's sending pace and the [good practices](/en/general/abuse/) reduce the risk of your number being blocked, but they do not remove it.
:::

## 1. Create your account

Create a free account at [dashboard.turbonotify.com](https://dashboard.turbonotify.com/auth/register). If you already have one, sign in and go to the next step.

## 2. Connect your main number

The main number is the WhatsApp that sends and receives your account's messages. You connect it in the dashboard:

1. In the dashboard, open <DashboardLink path="/numbers">Numbers</DashboardLink> and, on the **Main number** card, click **Connect main number**.
2. Choose **QR code** or **pairing code**.
3. On the phone, open WhatsApp at **Linked devices > Link a device**. For the QR code, point the camera at the screen. For the code, tap **Link with phone number instead** and type the code shown in the dashboard.
4. The card now shows the number as connected, and Turbo Notify appears under **Linked devices** on the phone with your organization's name.

To check it through the API, `GET /v1/numbers/main` returns `status: "connected"` (see [Status](/en/numbers/status/)).

## 3. Create an API key

In the dashboard, open <DashboardLink path="/api-keys">API Keys</DashboardLink> and create a key with the **Full access** template. The value is shown only once: copy it and store it somewhere safe. Every request carries the key in the `Authorization: Bearer YOUR_KEY` header (details in [API key](/en/general/access-key/)).

## 5. Receive replies

When someone replies, Turbo Notify produces a `message.received` event. You get it in one of two ways:

| Option | How it works | When to use it |
|---|---|---|
| [Webhook](/en/messages/webhook/) | Turbo Notify sends a signed `POST` to your endpoint for every event. Set the URL in the dashboard, under <DashboardLink path="/webhooks">Webhooks</DashboardLink>. Available from the SOLO plan. | You have a public HTTPS endpoint and want to react right away. |
| [Event polling](/en/messages/polling/) | You call `GET /v1/events` from time to time (scope `events:read`). Available on every plan. | You have no public endpoint, you are testing, or you are on the free plan. |

Both deliver the same events in the same format. To choose, see [Event polling](/en/messages/polling/).

## What can go wrong

| Response | What it means | What to do |
|---|---|---|
| `409 number_not_connected` | The sending number is not connected to WhatsApp. | Go back to step 2 and connect the main number. If it was connected, check that Turbo Notify was not removed from **Linked devices** on the phone. |
| `403 not_authorized` | The key is missing, wrong or revoked. | Check the `Authorization: Bearer YOUR_KEY` header. |
| `403 insufficient_scope` | The key lacks the operation's scope (`required_scope` names it). | Use a key with that scope, or the **Full access** template. |
| `400 invalid_phone_number` | The recipient is not a valid phone number. | Send the number with its country code, such as `+5511988887777`. |
| `429 send_rate_spacing` | You sent before the minimum interval between messages of your plan. | Wait the seconds in the `Retry-After` header. This pace protects your number. |
| `429 messages_quota_exceeded` or `402 contact_quota_exceeded` | The cycle's message or contact quota is used up. | See [Quota and usage](/en/usage/quota/). |
| Message with `state: "failed"` | WhatsApp did not accept the message. | The `status.error` field carries the code and a hint. See [Message status](/en/messages/status/). |

Every code is listed in [Error codes](/en/reference/errors/).
